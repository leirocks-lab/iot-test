# 重构后的 RN 设备模块开发规则

- 遵循根目录 [AGENTS.md](../AGENTS.md) 和 [原生与 RN 代码规范](../docs/SDD/原生与RN代码规范.md)。
- 本目录只承载设备控制、更多、设备内分享、定时及固件升级子流程，页面样式按蓝湖还原。
- HTTP/App 业务语义参考 V1.4；仅 MQTT 参考 V1.6 Corrected；本模块通过宿主服务调用相关能力，不直接持有生产通信连接或登录态。
- 全局导航、账号、安全存储、设备会话、配网、权限及升级任务由原生拥有；RN 只管理设备内部导航和展示状态。
- `../app-rn-old/` 仅供业务理解和结果对照，不约束新代码设计。按已确认流程、协议语义、视觉及最终结果重新设计实现；可选择复用已评审的资源、组件或测试向量，不要求沿用旧类型、接口、状态机、导航或依赖，也不要求逐文件搬迁或复刻旧缺陷。
- 已初始化独立依赖、锁文件、检查命令和设备模块入口。此前Android V2包已验证内置资源、只读观察、定时空态与返回；当前桥接V3增加原生页面关闭令牌，更多页面与V3新包仍待运行验收，不能引用旧包冒充。固件候选null契约阻塞；产品控制及完整设备业务尚未完成，iOS容器尚未在macOS构建运行。不得将基础入口、JS Bundle导出或局部读取成功作为完整设备业务或双端通过。目录、环境、注册名及产物命名见本目录与根README。
- 只有确需保留 Expo 模块且经双端验证后才引入；不因旧工程使用 Expo 自动继承全部模块、Router 或配置。
- 初始化后，所有 RN 检查从本目录执行；建立 lint、typecheck 和相关测试命令，按影响执行并记录结果。
- 本目录不通过 Expo prebuild 生成或覆盖 `../android-as/`、`../ios-as/`。
