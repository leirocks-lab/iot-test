# CHG-20261022-002 双蓝牙配网与可选参数占位

状态：draft；规范状态：draft。

## 问题与目标

用户报告Wi-Fi密码提交后显示添加失败，并明确指示绑定码非必填。0822 README 将0x04列入配网收齐流程，但没有实机证据证明其要求非空；PAIR-05查询必须有绑定码。用户随后确定两种蓝牙路线按广播UUID实现，无码时由当前账号HOME-01唯一MAC匹配确认绑定，且0822工厂确认0x8F发送零长度DATA。HOME-01缺MAC、无匹配或歧义时不能误报成功；空值的固件接受仍待实机验证。

## 影响与待确认

涉及两条 BLE GATT/加密路线、0822 0x04空字符串及12项计数、云端PAIR-05必填query与HOME-01可选MAC。用户确认0922的cipher在encrypt_note后加密，无码可用当前账号HOME-01唯一MAC匹配确认绑定，设备user_token直接使用App登录accessToken。用户最终更正为0822需发0x8F、DATA零长度；固件接受空DATA须实机验证。

用户本轮原话及前置依赖见[需求问询](<需求问询.md>)。两条路线按广播UUID分流、可选业务参数占位及无码HOME-01唯一MAC确认已明确；设备空码行为和真实云端字段仍待验收。
