# CHG-20261022-001 实施计划

## 输入与边界

关联[提案](变更提案.md)、[问询](需求问询.md)，RF-0020 1.5.0 / REQ-051 / AC-005、019、023。只修改密码校验器的必需性，未提供的真实配网参数不伪造。

## 实现方案

1. 先完成来源核查并更新 RF-0020 规范和版本记录。
2. `validateWifi` 保留 SSID 校验、密码非空及 UTF-8 254字节上限；没有校验器不抛配置缺失异常；提供校验器时继续透传原值并执行。
3. 将真实配网契约中的 `validatePassword` 改为可选，装配时只拒绝已提供但非函数的值；其他必需端口继续严格检查。
4. 使用合成端口验证省略校验器可继续进入0822编排、字符/空格不被修改、边界和额外规则拒绝在写入前发生；真实配置整体缺失仍显示其原有错误。

## 接口与兼容

无 REST、BLE 帧布局、存储或原生依赖变化，不需重新构建开发包。保留已装配密码校验器的行为及 Mock 规则。254字节由0822帧编码边界决定，不替代实际MTU检查或设备密码判定。

## 验证与交付

运行受影响 onboarding、app-runtime、provision-0822 测试及 lint、typecheck；生成索引并运行 specs:check。按任务清单记录实际结果。仅声明代码和合成测试完成，Android/iOS完整配网、硬件及云端绑定验收继续待实际执行；无实际发布不创建发布基线。
