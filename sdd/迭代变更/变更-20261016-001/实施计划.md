# CHG-20261016-001 实施计划

## 输入与边界

- 需求提案：[变更提案](变更提案.md)；业务问询：[需求问询](需求问询.md)。
- RF-0002 v0.5.0 / REQ-002；RF-0003 v0.3.0 / REQ-003、REQ-017；RF-0007 v0.4.0 / REQ-015；RF-0010 v0.3.0 / REQ-022。
- 只针对 P1 的 APP-01、AUTH-04、AUTH-05、AUTH-06 真实服务路径；注册、验证码、重置密码及任何 P2 不执行。
- 现有 development HTTP 接入以及两模块 API 根配置按 CHG-20261013-001。测试租户为用户指定 `tenant-id=1`，不猜测或自动尝试别的值。

## 实现方案

1. 建立本 CHG 的当日联调证据与逐 AC 结果，不先改业务服务代码。通过 RowanService → RealHttpClient 复测只读 APP-01；敏感请求体/凭据/Token 不写入证据。
2. 仅当用户此前测试账号凭据可由授权的本地安全配置取得时，调用 AUTH-04；响应业务码和所需字段完整后，进程内保存会话并按规范单飞执行 AUTH-05，检查刷新及安全存储行为。不能复用到期含义不明的数值做时间判断。
3. 会话建立且刷新验证完成后，按授权调用 AUTH-06；仅当在线响应成功时按规范清理本地会话。不得用模拟会话或伪造响应代替。
4. 若真实错误阻断后续链路，保存状态码、业务码、脱敏消息、时间、目标 API 与请求参数字段（敏感值脱敏），标出依赖链及未执行的 AC。先确认服务端事实；如发现需改变业务行为，另回到需求确认与规范审批流程。

## 接口与兼容

| RF | API | 契约用途 |
| --- | --- | --- |
| RF-0002 | APP-01 `GET /api/app/config` | 获取启动配置；保留最近有效缓存及明确禁用处理 |
| RF-0003、RF-0007 | AUTH-04 `POST /api/app/session` | `verify=password` 登录后安全保存完整会话；本轮不执行 captcha |
| RF-0003 | AUTH-05 `PATCH /api/app/session` | 恢复已保存 refresh token；不推断 expiresIn 单位/意义 |
| RF-0010 | AUTH-06 `DELETE /api/app/session` | 在线注销成功后清理当前会话 |

沿用已登记接口契约和适配器字段映射，无新接口、字段或依赖。

## 验证与交付

- 在实际 development Windows/Node 环境调用真实服务器，不用 Mock/单测响应冒充真实端到端结果。
- 逐项以 RF/AC 对应的操作、预期、实际值及脱敏 JSON 证据填入任务清单和联调结果。
- AUTH-04 失败时 AUTH-05/AUTH-06 真实前置不成立，应标记阻塞，不人工注入 token。
- C-003/C-016 保持待确认；未执行场景保持 `in_progress`，不改为 verified/released。
- 对 SDD 执行 `pnpm specs:index`、`pnpm specs:check`；无维护工具变更则不需 `pnpm specs:test`。本轮若无业务代码变更不执行额外业务测试。
