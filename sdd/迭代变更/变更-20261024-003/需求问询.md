# CHG-20261024-003 需求问询：配网服务恢复 HTTPS

日期：2026-10-24。范围：RF-0020、REQ-053/054、PAIR-04 四个设备侧服务地址，以及本地真实接口基址配置；不新增功能或接口。

## 已核实事实与来源

- Excel `APP功能清单` REQ-053/054 与 RF-0020 要求获取 PAIR-04 的认证、激活、绑定、OTA 四地址，再按所选 0922/0822 协议发送给设备。
- CHG-20261022-003 曾获用户授权，仅在 development 临时放行 HTTP 四地址。2026-10-23 实机到达 `A1 → A0 → C1` 后等待超时；HTTP 是否为原因未证实。
- 用户本轮明确提供 `https://47.107.80.36/iot/doc.html`、`https://47.107.80.36/doc.html`，并说明“后台接口都改成https了，包括PAIR-04接口的四个配网用的地址，改动代码适配”。两处文档入口在跳过证书校验时均返回 HTTP 200；PAIR-04 当前真实响应仍待登录后的实测。
- 直接 TLS 检查显示服务器使用 CN/SAN 为 IP `47.107.80.36`、签发者相同的自签名终端证书（`CA=false`）；Windows curl 正常校验返回 `SEC_E_UNTRUSTED_ROOT`，Node 返回 `DEPTH_ZERO_SELF_SIGNED_CERT`。连接的 Android 设备（API 31）上 `curl -I https://47.107.80.36/iot/doc.html` 返回 `SSL certificate problem: unable to get local issuer certificate`。HTTPS 路径存在不代表 App 或模组信任该证书。
- 2026-10-24 重建 development Android 包后，App 进程内无凭据 `HEAD https://47.107.80.36/iot/doc.html` 返回 200；探针仅用于本地验收，随后从业务代码移除。该结果只证明 App 对当前证书的信任，不代表独立的设备固件信任。

## 决策树与回答

1. 服务传输：后台与四个 PAIR-04 地址是否都改用 HTTPS？用户本轮原话已明确回答“是”。建议本地真实接口基址改 HTTPS，并撤销 development 四地址 HTTP 临时放行；理由是临时例外的上游条件已经改变，设备文档原本要求 HTTPS。
2. 依赖 1 的地址处理：App 是否可自行将旧 HTTP 响应替换为 HTTPS？既有确认要求发送 PAIR-04 原值；本轮没有授权改写。决定仍逐项校验、原值传输；若服务仍返回 HTTP，写入 BLE 前报错，作为后台未切换完成的证据。
3. 依赖 1 的证书信任：后台换公开受信任证书，还是仅开发包信任当前自签名证书？建议优先更换公开受信任证书，理由是 App 和模组均可沿用正常 TLS 信任。用户实际回答：“暂时不能，需开发包信任当前证书”。因此仅 Android development 构建内置当前证书；不禁用主机名、有效期或证书链校验，不扩大到 preview/production。最初计划采用 debug-only trust anchors，随后为本地 release 测试 APK 的冷启动及真实 HTTPS 联调改用 development 专属网络配置；这是开发构建范围内的实现调整，不把本地 release 测试 APK 视为 production 发布包。模组证书信任仍需设备端另行验证。

## 最终共同理解与残余限制

用户本轮直接确认了 HTTPS 目标和四地址范围，并明确选择“开发包信任当前证书”；以上三层决策均有实际回答。Android 开发包只额外信任已核对指纹的当前服务器证书，证书轮换后须重新核对并构建。规范仍为 draft，交付保持 in_progress。合成测试可验证 HTTPS 地址原样进入两种蓝牙协议，不能代替手机 HTTPS 请求、模组证书请求和云端绑定的实机验收。
