# CHG-20261024-003 实施计划

## 输入与边界

依据[变更提案](<变更提案.md>)和[需求问询](<需求问询.md>)，仅调整 RF-0020 v2.0.0 的 REQ-053/054 地址传输条件，关联 AC-007/019/024/026。两处后台文档入口使用用户提供的 HTTPS IP 地址。

## 实现方案

先更新 RF-0020 规范与版本记录。将当前真实环境的 App/IoT 模块根切换为 `https://47.107.80.36` 与 `https://47.107.80.36/iot`，示例同步；两条 BLE 协议复用的 PAIR-04 四地址检查在所有环境只接受有效 HTTPS，保持原值与字段顺序。Android 配置插件仅在 development 且指向当前后台时写入证书与 `base-config` 信任锚，并在生成清单中引用，使本地 debug 与 release 测试 APK 都可请求当前 HTTPS 后台；同时在该网络配置中保持既有 development 明文许可供 Metro 加载。其他环境显式清除旧生成清单入口及两个证书资源，避免在同一工作区切换构建环境时残留。证书文件在仓库保存固定指纹，构建时不从网络动态下载。保留已定义的设备阶段和错误呈现。

## 接口与兼容

PAIR-04 请求、Bearer Token 和响应四字段均不改变。旧服务若仍返回 HTTP 四地址，将在写入设备前被拒绝；不自动升级协议前缀，不把设备阶段超时解释为云端成功。已有 development/preview 业务 API HTTP 通用能力不属于本轮移除范围。无持久数据迁移；回退须经过新的 HTTPS/HTTP 服务事实确认。

## 验证与交付

运行两条协议及地址校验测试、配置验证、lint、typecheck、SDD 索引与检查。重新生成 Android 项目并构建开发包，核对清单、证书资源与手机实际 HTTPS 请求；再验证登录、PAIR-04 四地址、模组证书/激活/绑定阶段和账号唯一 MAC 匹配。当前服务器证书自签名，开发包信任不意味着模组信任；模组与云端未通过前不宣称真实配网成功。
