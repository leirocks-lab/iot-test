# CHG-20261012-001 邮箱注册验证页面

状态：in_progress

## 问题与目标

当前 RF-0006 注册表单将空验证码直接提交 AUTH-03，用户无法完成邮箱验证码验证。本次实现用户提供的邮箱验证页面，并按 AUTH-01 发送、AUTH-02 校验、AUTH-03 注册的既有顺序完成注册。

## 范围与规范差异

| 功能 ID | 原版本 → 目标版本 | 原始条目 | 变化前 → 变化后 | 关联 AC |
| --- | --- | --- | --- | --- |
| RF-0006 | 0.4.0 → 0.5.0 | REQ-010、REQ-011、REQ-012、REQ-014 | 注册表单直接调用 AUTH-03 并传空验证码 → 进入独立邮箱验证页，自动发送，输入六位验证码后校验并注册 | RF-0006-AC-001、002、004、005、006、008、014、015、016 |

用户明确要求：六位未填满时禁用确认；进入页面自动发送，成功时提示“发送成功”；60 秒后允许重发；错误验证码提示“验证码错误，请重新发送验证”并将六格边框变黄；验证码由系统输入法键盘提供，应用仅实现内容区域。

## 影响与待确认

- 只使用现有 AUTH-01、AUTH-02、AUTH-03 与 RowanService，不改 API 字段或数据持久化。
- 注册密码只在页面路由生命周期内保留，不进入 URL 参数或普通持久化缓存。
- AUTH-03 协议版本字段缺失（C-002）仍未解决，本次不得猜测或添加字段。
- GrillMe 技能入口不可用，用户明确授权本次跳过；授权和范围记录于 `需求问询.md`。
- Android/iOS 真机验收及真实邮箱投递不在当前可用环境内。
