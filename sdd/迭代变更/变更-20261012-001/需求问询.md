## 已核实事实及来源

- Excel 范围快照将 REQ-010 至 REQ-014 归属 RF-0006，分别覆盖发送验证码、输入与校验、密码设置、提交注册。
- RF-0006 已规定 AUTH-01 发送验证码、AUTH-02 校验验证码、AUTH-03 提交注册；当前 `RowanService` 实现了 `sendCaptcha(account, 'register')`、`checkCaptcha(account, code)` 和 `register(...)`。
- 当前注册界面提交时将空验证码直接传给 AUTH-03，尚无验证码输入页面。
- Mock API 的验证码有效期为 5 分钟，发送间隔为 60 秒，成功验证码为 `123456`；该行为只用于 Mock，不作为真实服务端策略承诺。

## 决策树

### 第 1 轮：注册提交与页面进入

1. 注册信息完成后如何处理？用户要求注册操作进入邮箱验证页，不直接提交注册；验证页进入时自动调用 AUTH-01。
2. 用户提供了页面参考图和内容范围吗？用户提供两张截图，并要求只实现页面内容区域，数字键盘使用系统键盘。

### 第 2 轮：验证码状态和完成条件

1. 确认按钮启用条件？用户要求六位验证码完整后才启用。
2. 初次发送与重发反馈？用户要求发送成功 toast；倒计时 60 秒结束后允许手动重发。
3. 验证码错误反馈？用户要求显示“验证码错误，请重新发送验证” toast，并将六个输入格边框设为黄色。
4. 成功流程？依 RF-0006 已确认的流程调用 AUTH-02 校验，然后 AUTH-03 注册；成功后进入登录流程。

## 用户最终共同理解

注册表单校验通过后进入独立的邮箱验证内容页，携带当前邮箱、密码和地区上下文。页面自动发送 register 邮箱验证码；成功后显示“发送成功”，并从发送成功时开始 60 秒倒计时。验证码由系统数字键盘输入，六位填满前确认按钮置灰。用户确认时先调用 AUTH-02，再调用 AUTH-03；验证码错误显示指定 toast 并将六格边框改为黄色。倒计时结束后可手动重发。注册成功后进入登录页，不把注册响应作为登录会话。

- AUTH-03 协议版本字段仍受 C-002 阻塞；本次不添加未定义字段。
- GrillMe 未执行，原因及用户对本次范围的跳过授权见上文。
