# CHG-20261012-001 实施计划

## 输入与边界

关联 RF-0006 0.4.0 → 0.5.0，REQ-010、REQ-011、REQ-012、REQ-014；验收 RF-0006-AC-001、002、004、005、006、008、014、015、016。详细业务决定见 `需求问询.md`。

## 实现方案

1. 注册表校验成功后在当前认证页面切换到邮箱验证内容，保留邮箱、密码和地区上下文，不把密码放入路由参数。
2. 验证页面挂载后请求 AUTH-01 register 验证码；仅发送成功后启动 60 秒倒计时并显示成功 toast。
3. 使用一个原生 `TextInput` 承载六位数字输入和系统键盘，在视觉上呈现六个输入格；不绘制键盘。
4. 六位输入后启用确认；先调用 AUTH-02，再调用 AUTH-03。错误验证码显示指定 toast 和黄色边框；其他网络/服务错误原样提示。
5. 倒计时归零后可手动重发；重复进行中的发送或确认请求不可并发。
6. AUTH-03 成功后清理验证状态并转到登录页，不自动登录。

## 接口与兼容

- AUTH-01 `GET /api/app/captcha`：沿用 `accountType=email`、`captchaType=register`。
- AUTH-02 `GET /api/app/captcha/{code}`：沿用现有 `checkCaptcha(account, code)`。
- AUTH-03 `PUT /api/app/user`：沿用 `register(account, password, captcha, regionCode)`。
- 不修改接口契约、持久化数据或平台原生目录。

## 验证与交付

- Mock 流程验证验证码发送、错误码校验、成功注册及会话保持未登录。
- 执行 `pnpm specs:index`、`pnpm specs:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`。
- Android/iOS 真机截图和系统键盘行为列为未执行项，不能据模拟环境声明通过。
