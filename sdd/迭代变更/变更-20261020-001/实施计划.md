# CHG-20261020-001 实施计划

## 输入与边界

- 关联：RF-0019；REQ-046、REQ-048；RF-0019-AC-002、RF-0019-AC-013。
- 复用 `AddDeviceFlow.scanIssue`、`Linking.openSettings` 和 Android 蓝牙设置 intent。
- 不修改 BLE/Wi-Fi 协议、扫描时限、发现结果去重或 API 契约。

## 实现方案

1. 新增可复用 `SystemRequirementsSheet` 底部抽屉组件，包含遮罩、圆角顶部、标题、说明占位和系统设置/取消操作。
2. 在 Add 页面将权限、蓝牙关闭、Wi-Fi 未连接/SSID 不可读状态映射到抽屉；保留现有状态机和显式重试。
3. “去系统设置”使用现有跨平台 `Linking.openSettings`，Android 蓝牙关闭优先使用 `android.settings.BLUETOOTH_SETTINGS`；不伪造应用内开关。
4. 补充组件单元测试或通过类型检查验证状态映射；执行规范索引、规范检查、lint、typecheck 和相关测试。

## 兼容性

不新增依赖。系统设置路由可能因平台版本变化失败，失败时保留抽屉并显示错误，不声明开关已开启。

## 页面还原返工方案（实现前记录）

1. 使用添加页专用发现布局，独立于通用 Page 的表单间距。按 375 点稿核对 44 点导航、16 点页边距、160 点雷达、14 点标题及三列推荐卡片。
2. 搜索面板随同一个滚动偏移连续收缩，紧凑状态占标题下方一行；不得保留两个同时可见的搜索区，不改变导航栏高度造成滚动跳动。
3. 增量发现结果先于推荐目录展示；显示真实目录匹配的图片、名称、型号与 MAC，图片或名称缺失只显示占位和已有字段，不补造商品或品牌。
4. 推荐列表按服务端品类分组，只展示 recommended=true 的产品。移除开发式筛选大按钮；保留详情确认路径。Shop 仅在已配置受信任 buyLink 时显示且打开该链接，产品选择使用卡片本身。
5. 扫描中不把状态机调试信息渲染成额外卡片；超时与未发现使用搜索面板表达，其他真实业务错误保留。
6. 使用实际 Web 预览在 375/390 点宽截图，并验证滚动、重新扫描、产品选择与抽屉；Mock 注入仅在本地检查脚本中使用，不修改生产路由和通信配置。记录截图与原生平台未验收限制。

验收映射：RF-0018-AC-001/005/009/012/015，RF-0019-AC-002/004/005/008/012/013/014。

## 已确认的扫描时长补充方案（实现前记录）

依据用户 2026-10-20 指令及“允许本次跳过并继续实现”的明确回答，本段实施 RF-0019 / REQ-046～048 的扫描时长调整，取代前文“不修改扫描时限”的原始边界；GrillMe 本次例外见同目录 `需求问询.md`。

1. 蓝牙发现默认窗口统一为 60000ms，并保留可配置入口；该配置不复用二维码识别/绑定等待时限。
2. 将同一窗口传入真实 BLE 和 Mock 适配器，消除真实扫描 25s 窗口/30s 外层预算与 Mock 提前返回导致的提前结束。真实射频监听覆盖整个有效扫描窗口。
3. 期限内增量显示发现设备、保持 scanning；期限届满统一结束并保留已发现结果，无结果时显示未发现及重新扫描。取消、选择设备、离页/切后台、权限或蓝牙错误继续及时退出。
4. 使用虚拟时钟验证默认 60s 和配置覆盖，包含晚到广播、去重、无结果、连续重扫、旧回调隔离及立即取消；不让其他配网测试真实等待一分钟。
5. 执行相关协议/流程测试、lint、typecheck、specs:index 后 specs:check；记录实际通过情况与原生平台未验收限制。

技术接线：默认配置使用 `src/config/device-discovery.ts`，验证时长为正整数且不超出 JS 定时器上限。沿用 AddOptions.scanTimeout 覆盖，将毫秒值传入 DeviceTransport.scan 的可选第三参数。原生扫描不再使用固定 25s/30s 窗口，准备权限的独立保护预算不得截短正常扫描；业务层总期限防止不响应的适配器一直忙碌，提前返回的适配器结果及时合并且页面等待完整窗口。Mock 同样按传入期限运行。正常到期（包括无结果）结束为 idle，不作为权限/蓝牙故障。测试直接使用短窗口或虚拟时钟。
