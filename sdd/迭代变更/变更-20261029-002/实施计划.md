# CHG-20261029-002 实施计划

状态：最终识别与卡片目标已确认；按先规范后代码顺序实施。

## 输入与边界

- 目标规范：RF-0017 2.0.0（draft、in_progress）；REQ-037～041；本轮实施 RF-0017-AC-003～006、013～015 的识别与展示部分。
- 设备码字段采用用户确认的 `deviceId` 与设备侧 `productId`；`bindCode` 只属于另行确认的分享码路径。
- 后续联网或 PAIR-06 绑定待需求方确认，本轮只给出卡片并明确提示未接入。

## 实现方案

1. 移除旧 `rowan.product` 解析、扫码路由和 PNG 样例；实现四字段 `rowan.device` v1 纯函数解析与类型校验，不把设备 ID 误称为 SN。
2. 相机与相册复用扫码状态机。单个有效首绑设备码直接执行产品核验，多码图片仍由用户选一个；重复帧只保留一次在途查询。
3. 按二维码 `productId` 查询 PAIR-01，以目录记录的设备侧 `productid` 唯一映射到云端 `id`，再调用 PAIR-02 并校验详情身份；失败留在扫码页，不展示伪卡片。
4. 成功时展示设备卡片，包含云端返回的产品图片、名称、型号和二维码中的“设备 ID”；点击只告知后续流程待确认，不发 PAIR-06、不开始蓝牙扫描或配网。
5. 保留现有分享码协议注入、单次绑定与未知结果核对边界；不得以首绑设备码触发分享绑定。

## 接口与兼容

- 复用 PAIR-01、PAIR-02；本轮首绑设备码无写接口。DEVICE-02 对未绑定账号可能返回无权限，本轮不依赖它核验未绑定设备真实性。
- 当前格式只为本 App 测试而定义，正式设备码及分享码不能默认兼容。旧产品码不再接收；以新设备码制作测试样例。
- 识别阶段只确认二维码格式和产品映射，不核实设备实际归属、MAC、SN、联机状态或绑定结果。

## 验证与交付

- 解析器：有效码、错误类型/版本/字段、空值、旧产品码拒绝、多码去重；不含 `bindCode`。
- 流程：单码相机/相册无需产品二次选择；PAIR-01 零/多匹配与 PAIR-02 身份不一致时阻断；成功只显示设备卡片，点击不发绑定或配网请求。
- 执行 lint、typecheck、相关自动化测试以及 `pnpm specs:index`、`pnpm specs:check`；Android/iOS 真机、真实二维码和后续配网绑定均须分别记录，未测不标 verified。
