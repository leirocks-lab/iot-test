# CHG-20261029-002 自定义首绑设备二维码识别

状态：业务决定已确认；识别与卡片实施中，后续绑定路径待需求方确认。

## 问题与目标

甲方尚未提供正式设备二维码编码。用户先要求自行确定简单测试格式，并在真机核对 Word V1.4 §5.2.2、Excel REQ-039 和扫码结果 UI 后，明确本轮只实现首绑设备码中的设备 ID、产品标识解析、产品详情映射与设备卡片。先前尚未交付的 `rowan.product` 产品码及样例按用户指令移除。用户要求在与需求方确认后再决定卡片之后调用 PAIR-06 还是进入配网。

## 确认的测试码与交互

- 四字段 JSON：`{"type":"rowan.device","v":1,"deviceId":"实际设备ID","productId":"LF-WM05"}`。`type/v` 是 App 本地格式标记，不传给后端；`deviceId`、`productId` 为非空字符串。旧 `rowan.product` 格式停用。
- `productId` 取设备侧标识，例如 `LF-WM05`；PAIR-01 中要求唯一匹配 `productid`，取得云端 `id`（样例 `prd_100`）后用 PAIR-02 读产品详情。零匹配、多匹配或详情身份不一致时阻断，不猜测映射。
- 相机或相册识别单个有效首绑设备码后，不再手选产品；展示带产品图片、名称、型号与“设备 ID”的卡片。设备 ID 不冒称为 SN；扫码识别不证明该设备真实存在、已联网或已绑定。
- 本轮卡片点击只提示后续流程待确认，不调用 PAIR-06、不进入蓝牙配网。首绑码不含分享 `bindCode`；分享码的编码、有效期与权限仍属 C-005。

## 影响与待确认

- 用户提供的 MQTT 模拟脚本在激活后才得到 `device_id`，只模拟 HTTPS 与 MQTT，不广播蓝牙；测试码使用的设备 ID 需来自实际已备案设备，不能从产品 ID 推导。
- 卡片之后到底按 Word V1.4 §5.2.2 调 PAIR-06，还是按 UI 进入配网再绑定，用户明确留待与需求方确认。该阶段不得被实现为自动动作。
- 分享码 `bindCode` 的来源、过期、一次性使用及设备 ID 映射继续由 C-005 跟踪；甲方正式设备码到来时另行核对兼容策略。
- 规范保持 draft、交付 in_progress；真机识别及真实后端验收按[任务清单](<任务清单.md>)记录，不把代码测试当作完整业务验收。
