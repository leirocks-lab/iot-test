# CHG-20261023-001 实施计划

先更新 RF-0020 规范与版本记录，再实现独立的 0822 固件通知解码：AES-CTR 参数及 LEN 校验保持，明文 CRC 使用非反射 `0x31` / 初值 `0x00` / 无最终异或。首条握手保持已获 ACK 的实机路径，`0x01～0x0A` 参数帧按固件报错及镜像 CRC 表改用非反射 `0x31`；十参数 ACK 全部完成但设备阶段超时后，单独将无 ACK 的 `0x8F` 改用同一 CRC 试验其计数条件。在调用点严格区分各命令，不用双算法宽松放行。移除前轮临时 CRC 探针。对原生 BLE 连接期和每次写入分别检查各自的取消信号，复用会话时不得检查已结束的旧连接预算。排队的固件拒绝帧与实时拒绝帧同样携带命令码给用户。对 `0x81/0x82` 空 DATA 接受已由实机观测支持的 ACK 形式，非空 DATA 仍比较原值。无码时只在 0822 `0x04` 报文使用字符串 `"0"` 占位，App 的绑定确认仍按无真实码分支查询 HOME-01。用两条实机回包的明文与 CRC 做独立向量测试，验证错误 CRC 拒绝及连续两次写入；运行相关测试、typecheck、lint、SDD 检查及 Android 实机复测，重点抓取 `0x8F` 后设备阶段及串口事件。未完成真实全链路时保持 in_progress。
