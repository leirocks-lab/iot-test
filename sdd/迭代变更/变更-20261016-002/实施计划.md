# CHG-20261016-002 实施计划

## Web fetch缺陷修复计划（实现前补充）

对应RF-0001-AC-008/014：先用要求this为globalThis的宿主fetch替身复现异常；默认FetchHttpClient包装调用globalThis.fetch，RealHttpClient未注入fetcher时委托其默认值。保留自定义fetcher、请求参数、AbortSignal、路由和错误传播。补平台及IoT两路回归，检查实际浏览器运行结果；lint、typecheck、针对性单测和SDD检查通过后记录证据。无Expo/RN API或原生配置变化，不重构业务流程，不声称旧APK已包含本次JS修复。

## 实现方案

1. 统一环境及API根验证：只允许development/preview/production；development/preview允许http/https，production只https；拒绝畸形URL、凭据、query、hash，模块根不含/app-api。App入口沿用development默认；底层直接使用未提供环境时按production严格验证。
2. RealHttpClient将环境传到FetchHttpClient，保持路由/租户/包络/会话隔离；不改变请求业务字段，不失败回落Mock。默认Mock继续可用。
3. app.config.ts按环境注入本地Android Config Plugin，在主Manifest明确设置usesCleartextTraffic；dev/preview=true、production=false。通过根配置生成原生工程，不手改android/ios。iOS根配置显式设置ATS按相同环境策略，以避免生产残留模板明文设置；iOS只做配置验证。
4. 更新配置矩阵：清除继承环境污染，检查双API根、低层默认严格、未知环境及URL错误；public和introspect配置检查实际Manifest/Info.plist。生产保留双真实模式校验。
5. 以确认的公开HTTP后台根在localhost网页运行真实HTTP模式，原生设备维度不伪装真实能力；只使用匿名启动配置或未登录产品响应验证可达性，不擅自提交注册、协议接受或业务写入。浏览器登录可供用户继续操作。
6. Android用已存在本地构建链验证CNG及开发包；真实安装/HTTP调用须实际连接手机才标通过。无设备时交付构建及明确待验步骤，不声称真机已通过。

## 接口与兼容

环境使用APP_ENV；真实HTTP双根、租户仍按已有公开配置。开发示例可用http://47.107.80.36及/iot，不嵌入测试密码/Token。无数据迁移，真实会话仍按模块根/租户隔离。MQTT、外链和模块协议不调整；iOS无Mac原生执行条件不虚报结果。
