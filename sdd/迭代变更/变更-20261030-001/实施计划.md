# CHG-20261030-001 实施计划

## 输入与边界

目标：RF-0017 3.0.0；REQ-039、REQ-041；RF-0017-AC-015～016。依据[提案](<变更提案.md>)和[需求问询](<需求问询.md>)。首绑码及产品信息卡片沿用 CHG-20261029-002 的已确认格式。

## 实现方案

1. 在服务层增加独立首绑 PAIR-06 方法，请求路径使用 `deviceId`，Body 省略 `bindCode`，禁用自动重试；分享绑定方法保持原契约。
2. 卡片点击由扫码状态机单次提交。核验 PAIR-06 返回的设备 ID、当前用户 ID、首绑角色；再读 HOME-01，确认当前账号列表包含该设备，才进入首页。
3. 明确服务端失败留在卡片显示错误；提交后超时/断网/响应不明只读 HOME-01 核对，未确认时保留待核对状态，禁止再次点击发写请求；允许手动再次只读核对。
4. 页面失焦及账号会话修订变更时隔离旧回调；绑定中禁用卡片重复点击。保持分享扫码独立处理。

## 接口与兼容

PAIR-06 `PUT /api/app/device/{deviceId}/user`，首绑不传 `bindCode`；返回 `deviceID/userID/bindingRole`。HOME-01 `GET /api/app/devices` 只读核对。旧 `rowan.product` 码仍不接收；不更改二维码编码。无本地数据迁移。

## 验证与交付

自动化验证正常成功、返回身份不一致、明确失败、超时后 HOME-01 已有/尚无设备、重复点击、账号切换。执行 lint、typecheck、相关测试、`pnpm specs:index` 与 `pnpm specs:check`。真实 Android/iOS、真实服务端和设备归属另行验收并留证；无真实结果不标 verified。
