# CHG-20261024-001 配网服务恢复 HTTPS

状态：HTTPS 与开发包证书信任范围已由用户确认；实机验收待完成。

## 问题与目标

当前真实 App/IoT 基址仍为 HTTP，开发环境的 PAIR-04 四地址存在临时 HTTP 放行。后台现已改为 HTTPS，App 应使用两个 HTTPS 模块根；0922/0822 仅将 PAIR-04 返回的四个有效 HTTPS 地址原样交给设备。旧 HTTP 响应应在首个 BLE 写入前明确拒绝。

## 范围与规范差异

| 功能 ID | 原版本 → 目标版本 | 原始条目 | 变化前 → 变化后 | 关联 AC |
| --- | --- | --- | --- | --- |
| RF-0020 | 1.8.0 → 2.0.0（MAJOR：撤销 development HTTP 验收行为）→ 2.1.0（MINOR：补充本地 release 测试包验收） | REQ-053/054 | development 可发送 HTTP 四地址 → 所有环境均要求 HTTPS 四地址；Android development 本地测试构建额外信任当前证书 | RF-0020-AC-007/019/024/026/034 |

不改变 PAIR-04 路径/字段、BLE 报文、绑定规则或其他开发环境本地 HTTP API 能力；只把本次真实后台配置切换为 HTTPS。

## 影响与待确认

影响本地 `.env.local`、示例基址、共用的四地址预检查、两条协议测试及 Android development 构建。服务器当前自签名证书不被本机系统信任；用户已选择仅开发包信任当前证书。模组是否信任、PAIR-04 是否实际返回四个 HTTPS 地址均未证实。不得全局禁用证书校验。
