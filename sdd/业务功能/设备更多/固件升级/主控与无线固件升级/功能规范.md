## 前置条件与业务规则

以下保留 Excel 原始说明用于追溯，其中 REQ-094/095 的 API 编号与动作冲突。原文不是已冻结的执行契约；草稿流程按 API 列和 Word Method/Path 关联，必须先解决 C-001。

- **REQ-091 / 检查 MCU 固件**：调用 OTA-01 检查 MCU 固件版本；是否有升级及版本信息由云端返回。
- **REQ-092 / 检查 Wi-Fi 固件**：调用 OTA-02 检查 Wi-Fi 固件，必须带设备权限认证。
- **REQ-093 / 创建升级任务**：调用 OTA-03 创建升级任务；REST 成功仅表示任务创建，不代表设备升级完成。
- **REQ-094 / 升级进度**：调用 OTA-04 查询任务状态和进度；最终结果以任务状态及设备回报为准。
- **REQ-095 / 取消升级**：在任务允许取消时调用 OTA-05；执行中不可取消时应展示明确状态。

所有功能遵循 [公共规则](<../../../../公共规则/业务规则.md>) 和 [API 约定](<../../../../公共规则/接口约定.md>)。

### 本轮问询采纳的业务决定

依据 [CHG-20261007-005 设备更多 问询记录](<../../../../迭代变更/变更-20261007-005/业务问询/设备更多.md>)。以下是业务规范目标，接口缺失时不得按猜测参数实施。

- OTA-01检查MCU，OTA-02检查Wi-Fi；保留Excel原编号矛盾，执行映射按Word Method/Path：OTA-05 GET查询，OTA-04 DELETE取消。
- 创建请求前校验已知在线状态、固件类型和匹配信息；1512/1514/1515等按服务端真实结果处理。
- 任务状态为updating只显示正在升级；无progress字段不显示模拟百分比；success/failed/cancelled停止轮询。
- 取消确认成功后仍查询最终状态，不把取消请求成功解释为设备回滚或升级完成。

### 问询具体决定

- RF-0045-Q-001：先选择已返回的固件类型及版本，显式确认升级；同设备升级期间不重复创建任务。
- RF-0045-Q-002：前台按5秒查询；离页停止界面轮询、保留当前账号的任务引用，返回重新查任务；仅服务端允许状态提供取消。

### 本轮确认的实施边界（CHG-20261014-008）

- OTA-01/02 已部署响应的 `hasUpdate=false、firmware=null` 是已最新或无可用新版本的正常结果；`hasUpdate=true` 时展示实际固件版本和说明，固件/设备身份不匹配时不允许提交。已绑定账号可操作，后端仍鉴权；不以客户端 Mock 的管理员限制收窄范围。
- OTA-03 是会创建任务的 PUT，同一确认只发一次，401/超时不自动重发。发送前持久记下本账号本设备的待核对状态；取得有效 taskID 后保存任务引用并查询，REST 创建成功不当作升级完成。响应未知且无 taskID 时保留待核对并阻止再次创建，等待服务端任务发现/幂等核对能力。
- OTA-05 依据部署响应的 `result/status/progress/startedAt` 及可选时间字段展示状态与有效 0～100 进度，适用于 MCU/Wi-Fi 的当前 taskID。前台每 5 秒查询，后台或离页停止；success/failed/cancelled 为终态。查询失败不等于升级失败，未知状态不臆断成功。
- 部署 OTA-04 允许 waiting/downloading/upgrading 非终态请求取消；确认后只发一次，DELETE 成功或终态竞态均重新读 OTA-05，不把取消响应当作回滚。取消结果未知不自动重发。账号/设备切换时隔离在途请求和本地任务展示。

## 主流程与异常流程

### 主流程

1. 认证读取对应固件检查结果并展示版本与remark。
2. 确认后OTA-03带type及firmwareID，取得taskID。
3. 按OTA-05查询该taskID；用户请求取消时依据允许状态调用OTA-04带taskID并再查询结果。

### 异常流程

- 任务创建响应未知时不自动重建；保留结果未知，等待任务可查询性契约。
- 网络查询失败与升级failed不同；权限丢失停止轮询；未知result不解释成功。

## 验收标准

- **RF-0045-AC-001**：正常场景验证：OTA-01/02 检查版本，OTA-03 创建任务，OTA-05 查询结果，允许时以 OTA-04 取消任务。
- **RF-0045-AC-002**：异常场景验证：离线、固件不匹配、任务不存在或升级失败明确提示；任务创建成功不等于升级完成。
- **RF-0045-AC-003**：针对 REQ-091「检查 MCU 固件」执行场景验收，观察结果必须满足：调用 OTA-01 检查 MCU 固件版本；是否有升级及版本信息由云端返回。
- **RF-0045-AC-004**：针对 REQ-092「检查 Wi-Fi 固件」执行场景验收，观察结果必须满足：调用 OTA-02 检查 Wi-Fi 固件，必须带设备权限认证。
- **RF-0045-AC-005**：针对 REQ-093「创建升级任务」执行场景验收，观察结果必须满足：调用 OTA-03 创建升级任务；REST 成功仅表示任务创建，不代表设备升级完成。
- **RF-0045-AC-006**：针对 REQ-094，按用户确认的部署映射以 OTA-05 获取任务状态与可用进度，终态停止轮询；不能对查询操作发送 DELETE。C-001/C-010 的来源冲突与真实验收仍追踪。
- **RF-0045-AC-007**：针对 REQ-095，按用户确认的部署映射仅在允许状态通过 OTA-04 取消；终态不可取消须明确展示，不能用 GET 当作取消。C-001 的原文冲突仍追踪。
