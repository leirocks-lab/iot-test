## 前置条件与业务规则

以下规则直接来自 Excel；Word 的补充仅用于明确范围内行为，冲突见末节。

- **REQ-049 / 网络检查**：读取系统当前网络能力；引导使用 2.4GHz，无法判断频段时仅提示而不阻断流程。
- **REQ-050 / SSID 展示**：展示当前 Wi-Fi SSID；未连接或无权限时提供系统设置引导，并按 iOS/Android 能力降级。
- **REQ-051 / 密码输入**：支持密码显隐和本地校验；Wi-Fi 密码不得进入普通业务日志或上传无关云端接口。
- CHG-20261022-001：真实0822默认仅校验密码非空及UTF-8不超过254字节；来源未规定的复杂度、字符种类、自设最短长度或8～63位限制不添加。缺少额外密码校验器不构成配置错误；已提供且有明确依据的校验器仍执行。SSID与密码保留原始UTF-8，不trim、不截断。空值失败见新版README §6.2，报文上限见§6.1；开放网络能力不在本次变更中确认。
- **REQ-052 / 配网帮助**：Wi-Fi 输入页和失败页调用 PAIR-07，按 productID 与语言返回文本或受信任帮助链接。
- **REQ-053 / 获取服务地址**：进入二期配网前调用 PAIR-04 获取认证、激活、绑定和 OTA 服务地址。
- **REQ-054 / 统一进度状态机**：将连接设备、认证、发送 Wi-Fi、激活、绑定、证书及服务器连接映射为统一状态和错误码。
- **REQ-055 / 绑定结果轮询**：调用 PAIR-05，轮询间隔不低于 2 秒并设置总超时；绑定成功后立即停止轮询。
- **REQ-056 / 配网失败**：展示具体失败阶段、重试、FAQ 和返回入口；不得把网络失败误报为设备故障。

所有功能遵循 [公共规则](<../../../../公共规则/业务规则.md>) 和 [API 约定](<../../../../公共规则/接口约定.md>)。

### 本轮问询采纳的业务决定

依据 [CHG-20261007-005 添加设备 问询记录](<../../../../迭代变更/变更-20261007-005/业务问询/添加设备.md>)。以下是业务规范目标，接口缺失时不得按猜测参数实施。

- Wi-Fi 密码仅在当前配网上下文内使用，不写普通日志或发无关REST；离页/结束清除本次秘密。
- 显示连接设备、认证、发送Wi-Fi、激活、绑定、证书及服务器连接的真实阶段；不收到阶段事件时不伪造进度。
- PAIR-05 的1121表示继续等待，1122/1123停止并按真实错误显示；成功立即结束轮询。
- 总超时数值不自行选取，必须由协议方确认并在实施前冻结；未知原生字段不当生产参数。

### 问询具体决定

- RF-0020-Q-001：按系统能力明确降级；无法确定频段时仅提示使用2.4GHz，不阻断；SSID未能读取与未连接分别提示系统设置，绝不推测频段或显示假SSID。
- RF-0020-Q-002：由产品已冻结能力决定阶段；一期按原生真实结果执行 PAIR-06，二期先 PAIR-04 后真实原生步骤与 PAIR-05；统一状态只映射真实事件，不填百分比或模拟完成。
- CHG-20261021-002：配网页弧形进度仅按已收到的真实 A/C/B/D/E/F 阶段事件逐点显示；阶段事件未知时保留当前值，绑定查询结束前保留未完成槽位，不以动画或百分比推断设备完成。
- RF-0020-Q-003：绑定成功/确认失败/达到已冻结总超时立即停轮询，间隔不低于2秒；离页停止App监听及轮询，不能宣称设备端已取消；结果未知先核对，不自动重复绑定或自动重发Wi-Fi。

## 主流程与异常流程

### 主流程

1. 检查产品能力、系统Wi-Fi状态与权限，提示2.4GHz，输入并按确认规则校验密码。
2. 按已确认一期/二期路线启动真实原生流程；二期先获取 PAIR-04 服务地址。
3. 接收阶段事件并以不低于2秒间隔 PAIR-05 查询真实绑定结果。
4. 成功停止流程进入 RF-0021；失败显示具体阶段、重试、FAQ与返回入口。

### 异常流程

- 无法识别网络频段不阻断；已确认不支持的网络按产品约束提示。
- 网络错误不标设备故障；离页停止客户端活动但不声称取消云端任务。
- 帮助加载失败不替代配网失败原因，可重试帮助或返回；未知绑定结果不自动消费绑定码。

## 页面拆分补充（CHG-20261020-002）

Wi-Fi 输入、配网进度、绑定结果、昵称和完成状态统一呈现在独立配网页。该页面由搜索页在设备和产品能力确认后进入，也可承接扫码绑定的已有带参入口；不因路由拆分新增接口或改变 AddDeviceFlow 状态语义。

- **RF-0020-AC-021**：从蓝牙发现页选择并确认设备后，独立配网页展示已确认产品、当前 Wi-Fi、密码输入和配网操作；搜索动画、发现列表和推荐目录不出现在配网页。
- **RF-0020-AC-022**：配网页离开、失败、未知绑定、昵称设置和完成结果继续使用既有状态机；路由参数不包含 Wi-Fi 密码、绑定码或访问令牌，离页清除密码并停止客户端活动。

## 双蓝牙配网与可选业务参数（CHG-20261022-002）

用户明确要求两种配网均实现，由已验证的设备广播 Service UUID 决定：0922 使用旧版 JSON/分包/AES-CBC；0822 使用新版二进制/AES-CTR/逐项 ACK。已确认产品须支持 Wi-Fi 与蓝牙，配网能力列表含 B 或 C 时可进入这两条路线，最终协议仍由广播UUID选择。App 将同一事务中的 SSID、密码、登录accessToken作为设备user_token、产品身份及 PAIR-04 返回的认证、激活、绑定、OTA 四地址按对应协议发送。无有效广播 UUID 不猜测路线。依据固件旧配网成功参考及用户本轮确认，0922先发送明文`cipher`（SHA-256前16字节的大写32位十六进制），收到并校验明文`cipher_reply`后才发送明文`encrypt_note`，随后将`apinfo`的AES-CBC原始密文字节按BLE协议分包发送；设备到App的加密状态通知采用Base64文本。身份校验失败或超时不得继续发送Wi-Fi凭据。0822在验证0x0F后发送DATA零长度的0x8F，再发送0x01～0x0A；空DATA的固件接受须实机验证，规范保持draft。

绑定码未取得时，0822 的 `0x04` 与 0922 的 `binding_code` 均发送字符串 `"null"` 作为协议占位；不得因缺码在写入前直接判添加失败。0822 的原空值曾被本机 `0x14` 拒绝，0922 的原空字符串曾使后台返回 `meta.code=-1`；0822 的字符串 `"null"` 已有设备绑定 `D0` 实机证据，0922 路线尚待复测。此默认值仅用于模组报文，不作为 App 已取得真实绑定码，也不用于 PAIR-05 查询。设备及云端是否接受占位码以实际结果为准。有可查询的真实绑定码时仍以 PAIR-05 确认；无码时轮询当前账号 HOME-01，只有广播 MAC 匹配唯一设备 ID 且角色有效才算绑定成功。无 MAC、未出现或歧义保持待确认，不把设备联网状态或发送完成当作添加成功。

### 0822 固件回包校验（CHG-20261023-001）

真实 0822 模组通知的帧头和 LEN 正确后，以既有 MAC/型号密钥及全零 IV 解密；对明文 PAYLOAD 按非反射 CRC8 多项式 `0x31`、初值 `0x00`、无最终异或校验。该方向由首条 `0x80 + ok` 与 `0x0F` 工厂挑战两条实机向量共同支持。App 发出的 `0x00` 握手保留已收到 `0x80` ACK 的原编码；`0x01～0x0A` 参数帧按下文 AC-030 受限试验采用非反射 `0x31`。十参数 ACK 全部收到但阶段等待超时后，`0x8F` 工厂确认按 AC-033 改用非反射 `0x31` 试验其无 ACK 的 CRC 计数条件。各命令只按其指定算法严格校验，不同时宽松接受双算法。固件源码尚未取得，规范保持 draft；最终阶段及云端结果仍按真实回报验收。

- **RF-0020-AC-027**：给定上述两条模组回包向量，App 均通过帧头/LEN、解密及设备方向 CRC 校验并继续按 0822 时序处理；任一 CRC 字节被篡改时拒绝，不能因双算法兜底放行。握手出站帧保持已收到 ACK 的既有编码，参数及工厂确认出站帧另按 AC-030/033 试验；不把此项合成通过称为完整配网成功。

同一 0822 蓝牙连接在首条握手事务完成后继续承载工厂确认与十项参数。连接期的取消信号只约束建立连接；连接成功后每次写入以通道是否已关闭及该次写入的取消信号判断，不能因前一笔操作的预算正常结束而中断后续写入。

- **RF-0020-AC-028**：给定 0822 连接成功且首条写入/ACK 完成，其连接期预算随后正常结束，App 继续在同一通道发送 `0x8F` 及后续参数时不因旧信号误报“蓝牙连接已停止”；通道实际断开或当前写入被取消时仍及时失败。

固件拒绝帧无论在 App 等待应答时到达，还是先进入通知队列、稍后被读取，都要保留实际十六进制命令码供用户及联调人员定位；未知码不擅自解释为某个参数失败。

- **RF-0020-AC-029**：给定 0822 固件拒绝帧先于对应等待建立而进入通知队列，配网页显示该帧实际命令码，且不把“设备拒绝配网参数”作为唯一错误信息。

串口实机报告 `set_ssid crc8 check fail!` 与 `0x71` 同步出现。当前按仓库固件镜像里的非反射 `0x31` 表对 `0x01～0x0A` 参数帧试验，首条 `0x00` 握手保留当前已收到 ACK 的编码；十项参数逐项 ACK 已在 2026-10-23 实机走通，但设备阶段仍超时，不把推断写成已批准固件契约。

- **RF-0020-AC-030**：给定同一设备完成握手与工厂确认，App 发送 `0x01` SSID 帧时应通过模组 CRC 检验并获得对应 ACK 或明确业务拒绝；后续参数采用相同候选 CRC 的结果逐项记录，未验证项保持待验收。

2026-10-23 实机确认 `0x01` 后收到命令 `0x81` 且 DATA 为零长度；文档写“SSID 回显”与该设备行为不符。按当前实机行为，以已校验 CRC 的对应 ACK 命令确认零长度 DATA；若 `0x81/0x82` 携带非空 DATA，仍要求与原始 SSID/密码逐字节一致。此例外只限两项 Wi-Fi 参数 ACK，不扩大到错误码或其他命令。

- **RF-0020-AC-031**：给定固件返回 CRC 正确且命令匹配的 `0x81/0x82` 零长度 DATA，App 不报“Wi-Fi 参数回显不一致”并进入下一参数；若 DATA 非空但与原值不同，则拒绝继续，且诊断日志不输出 SSID 或密码内容。

2026-10-23 实机进入绑定码参数后返回 `0x14`，与文档中该命令空值错误相符。用户此前明确授权无法取得的参数可传 `0` 或空字符串；当前 0822 设备已证明空字符串被拒，因此采用字符串 `"0"` 进行受限联调。该占位码能否通过设备云端绑定尚未确认。

- **RF-0020-AC-032**：给定业务未取得绑定码，0822 `0x04` DATA 写入 UTF-8 字符串 `"0"`，App 的无码身份仍为空并仅用 HOME-01 的唯一 MAC 匹配确认绑定；真实绑定码存在时发送原码并走 PAIR-05。模组若继续返回错误，应显示实际命令码且不得宣称绑定成功。

2026-10-23 十个参数 ACK 均通过后等待设备阶段 120 秒仍超时。文档 §6.2/6.4 规定 `0x8F` 无 ACK，仅 CRC 正确才增加 `get_info_flag`，累计 12 项后触发 Wi-Fi；原 `0x8F` 用反射 CRC `0xCD`，非反射候选值为 `0x54`。此前后续参数 ACK 无法证明无 ACK 的 `0x8F` 已计数，因此仅调整其 CRC 并用实机阶段事件验证，不改变已获 ACK 的 `0x00` 握手。

- **RF-0020-AC-033**：给定设备工厂挑战通过，App 的零长度 DATA `0x8F` 使用非反射 `0x31` 明文 CRC；十参数 ACK 完成后必须观察模组进入 `A1` 或其他真实阶段/明确失败，不以 120 秒超时推断成功。若仍无阶段，记录串口与通知证据并保持待验收。

2026-10-23 实机已证明上述修正可进入 `A1 → A0 → C1`；当时 PAIR-04 四个地址均为 HTTP，设备在证书请求阶段没有继续发出 `C0` 或明确失败帧，120 秒后 App 超时，设备随后重新进入 `AP_UP`。是否因当时的证书 URL、固件 HTTP 能力或云端设备接口造成，仍需设备端请求日志与云端响应证实。此阶段不得标记完整配网或绑定验收通过。

## 后台与 PAIR-04 地址切换 HTTPS（CHG-20261024-003）

用户说明后台两个模块入口及 PAIR-04 返回的认证、激活、绑定、OTA 四地址均已切换为 HTTPS。当前真实运行配置分别指向 `https://47.107.80.36` 与 `https://47.107.80.36/iot`。0922/0822 在首个 BLE 写入前逐项检查 PAIR-04 四地址：必须为无首尾空白、有主机的有效 `https:` URL；所有运行环境一致。App 保留服务端地址原值及顺序，不自动将旧 HTTP 改为 HTTPS。通过地址检查只允许继续发送，不代表设备已连云或账号绑定成功。

- **RF-0020-AC-026**：给定四个有效 HTTPS 地址，development、preview、production 的 0922/0822 路线均按认证、激活、绑定、OTA 顺序将原值发送给设备；任一地址为 HTTP、缺失、格式错误或含首尾空白时，在首个 BLE 写入前拒绝，不显示添加成功。证书握手、设备云端阶段与账号绑定仍需实机验收。

2026-10-24 对两个 HTTPS 文档入口的直接 TLS 检查发现服务器使用自签名证书，系统默认不信任。用户已选择下述开发包信任方案；在开发包重新构建并实测前，不能把文档入口可访问或合成测试通过视作真实 HTTPS 配网验收。[本轮问询](<../../../../迭代变更/变更-20261024-003/需求问询.md>)、[提案](<../../../../迭代变更/变更-20261024-003/变更提案.md>)和[任务清单](<../../../../迭代变更/变更-20261024-003/任务清单.md>)记录证据与限制，规范仍为 draft / in_progress。

## iOS 手动 SSID 降级（CHG-20261029-001）
