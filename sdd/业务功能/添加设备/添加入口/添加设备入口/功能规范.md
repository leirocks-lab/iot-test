# RF-0016 添加设备入口

> 0.2.0：使用 GrillMe 对本功能建立决策树；依据用户“问询所有剩下业务，并直接采纳建议”的明确批量授权采纳业务建议。协议与来源缺口仍待确认，不表示已实现或通过业务验收。

## 目标与边界

面向 ROWAN App 用户和本功能实施人员，完成「添加设备入口」。业务归属：添加设备 / 添加入口。

仅覆盖 REQ-036。页面状态和接口是本功能的组成部分；其他资料中的额外功能不纳入。

## 前置条件与业务规则

以下规则直接来自 Excel；Word 的补充仅用于明确范围内行为，冲突见末节。

- **REQ-036 / Add 菜单**：从首页 Add 进入，提供扫码、蓝牙发现、手动选择和推荐产品等添加方式。

所有功能遵循 [公共规则](<../../../../公共规则/业务规则.md>) 和 [API 约定](<../../../../公共规则/接口约定.md>)。

### 本轮问询采纳的业务决定

依据 [CHG-20261007-005 添加设备 问询记录](<../../../../迭代变更/变更-20261007-005/业务问询/添加设备.md>)。以下是业务规范目标，接口缺失时不得按猜测参数实施。

- 所有入口共用添加流程且一次只允许一个活跃添加上下文；选择方式与绑定成功分开。
- 无产品可用时保留方式说明与重试，不生成默认设备或产品。

### 问询具体决定

- RF-0016-Q-001：统一承接 Home 右上 Add 与无设备添加按钮，进入同一添加菜单；仅提供扫码、蓝牙发现、手动选择和推荐产品，不恢复底栏居中 Add 或增加商城。
- RF-0016-Q-002：仅选择对应方式后申请相关权限；菜单打开和产品目录浏览不触发无关权限，取消返回原入口而不产生绑定。

## 主流程与异常流程

### 主流程

1. 从首页已确认入口打开添加菜单。
2. 用户选择范围内方式，交给对应 RF；仅在需要时请求系统权限。
3. 取消或返回结束当前添加上下文并回到原首页视图。

### 异常流程

- 未登录时转账号入口，不能匿名绑定。
- 相机被拒绝不阻止手动目录入口；返回不宣称添加成功。

- REQ-036：PAIR-01 获取产品列表（GET /api/app/products）；
PAIR-02 获取产品详情（GET /api/app/products/{productID}）；
PAIR-06 设备绑定用户（PUT /api/app/device/{deviceId}/user）

API 字段大小写按契约保留；物模型属性、服务和事件按产品能力确认。这里只引用范围内所需能力，不新增 REST 设备控制或后台管理接口。

## 验收标准

- **RF-0016-AC-001**：正常场景验证：Add 菜单可进入扫码、蓝牙发现、手动选择或推荐产品的范围内流程。
- **RF-0016-AC-002**：异常场景验证：取消添加返回原入口；不得把导航选择等同于设备已绑定。
- **RF-0016-AC-003**：针对 REQ-036「Add 菜单」执行场景验收，观察结果必须满足：从首页 Add 进入，提供扫码、蓝牙发现、手动选择和推荐产品等添加方式。

验收证据在后续 `迭代变更/<变更ID>/任务清单.md` 中记录平台、测试输入、结果与关联验收编号。本轮只完成规范整理，不将这些业务验收标记为通过。
