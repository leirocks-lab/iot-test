# RF-0014 长按多选与批量删除

> 2026-10-13：关联 CHG-20261013-002，按用户首页设计稿细化品牌、房间标签、产品卡片和选择模式视觉；保持现有 API 与状态语义。

> 0.2.0：依据两轮 GrillMe 问询及用户最终确认重新生成。业务决定已记录，接口与依赖未完全冻结；保持 draft / unplanned，不表示已实现或已通过业务验收。

## 目标与边界

允许从首页长按选择设备，并逐台解除当前用户与选中设备的绑定，清楚报告部分成功与结果未知。仅覆盖 REQ-031、032；“删除设备”指解绑当前用户，不能解释为物理删除设备或删除其他用户关系。

## 前置条件与业务规则

所有功能遵循 [公共规则](<../../../../公共规则/业务规则.md>) 和 [API 约定](<../../../../公共规则/接口约定.md>)。已确认决定详见 [CHG-20261007-004 需求问询](<../../../../迭代变更/变更-20261007-004/需求问询.md>)；本次不实现 App 代码，不将文档检查作为业务验收。

- 长按卡片进入多选态，显示选择控件、选中数量、取消/完成与删除入口；支持选择和取消选择。零选择时删除不可提交。
- 编辑期间先取消或完成才能切换房间或底部导航；取消/完成退出编辑并清除本次选择，不调用解绑。编辑态卡片操作不能触发设备页或快速开关。
- 提交前确认当前选中数量与“仅解除本人绑定”含义；取消确认不产生 API 请求。确认后冻结本次设备集合，逐台调用 MORE-02。
- 执行期间禁用重复提交及选择变更，不允许重复发送同一批请求；普通离线设备状态不等于云端解绑失败，服务端权限和结果决定实际处理。
- 逐台汇总成功、明确失败、结果未知。确认成功项移除卡片并清除其缓存及订阅；失败/未知项保留，禁止将部分成功显示成整批成功。
- 全部确认成功后退出编辑；有失败则保留失败项选中及逐台原因，允许只处理失败项或退出。解绑结果未知时先刷新绑定关系，不自动重发 DELETE；已解绑错误和幂等语义按 C-019 冻结后处理。

## 主流程与异常流程

### 主流程

1. 长按进入编辑，选择设备并查看实时选择数量；取消/完成可退出而不解绑。
2. 点击删除，确认数量及解绑含义；确认后固定设备集合并进入执行态。
3. 逐台 MORE-02，分别记录结果；确认成功时清理对应卡片、缓存和订阅。
4. 全成功退出；部分失败保留失败项选择与结果，结果未知先重新读取 HOME-01 核对绑定关系，再按冻结契约处理。

### 异常流程

- 未选设备或取消确认：不发送解绑。编辑中尝试换房间/底栏：保持编辑并提示先结束编辑。
- 部分明确失败：只移除成功项，失败项保留且显示原因；手动再次操作不能包含已经确认成功的项。
- 发送后网络中断或响应丢失：显示结果未知，先刷新核对；不可把未收到响应视为服务器未执行，也不可把 1361/1362 猜为成功。

## 验收标准

- **RF-0014-AC-001**：给定至少两个可选设备，长按后可选择/取消；确认解绑后每台分别调用 MORE-02，展示各台结果。
- **RF-0014-AC-002**：给定一台成功一台明确失败，只移除成功项，失败项保持选中并显示原因，不显示整批成功。
- **RF-0014-AC-003**：给定编辑态，选择/取消使数量正确变化；取消或完成退出且不发送解绑，尝试切换房间/底栏须先结束编辑。
- **RF-0014-AC-004**：给定确认的 deviceID 集合，逐台调用 MORE-02 并汇总；无需新增批量接口，成功项清理缓存和订阅。
- **RF-0014-AC-005**：给定零选择或用户取消数量确认，不产生 DELETE；确认文案说明解除本人绑定。
- **RF-0014-AC-006**：给定批次执行中，再次提交或选择变更被禁用，不重复下发同一批解绑。
- **RF-0014-AC-007**：给定全部确认成功，退出编辑并清除选择；给定部分失败，保留失败项选择，手动处理仅涉及失败项。
- **RF-0014-AC-008**：给定请求结果未知，显示未知并先刷新绑定关系，不自动重发；未冻结错误含义不得被映射为解绑成功。

既有 AC 编号保持原意并细化可观察场景，新场景顺序追加；验收执行结果在变更包记录，本轮不将以上业务验收标为通过。
