## 添加设备契约接线

`createRuntime(config, realDriver?, contracts?)`第三参数可接本范围已确认端口：`contracts.onboarding`采用`RealAddContract`（profile.factoryReply、profile.stageTimeout、makeBindCode、可选validatePassword、deviceToken、bindingTimeout、operationTimeout）；`contracts.qr`采用正式`RowanCodeParser`；`contracts.wifi`可替换系统读取端口。默认Android/iOS真实模式加载原生BLE/系统Wi-Fi；Mock保持隔离。

这些端口是后续接线位置，不是新协议事实。首配码必须对应实际云端关联，二维码解析端口必须按正式字段/编码提供，Token规则来自目标固件确认；预算需冻结生产数值，测试中的合成载荷/码/时长不复制为生产配置。旧V1.1写过8F="ok"，已选新版尚未证实，不能直接默认。UI同事可复用Add状态和核对入口，不需重写业务编排；完整MQTT会话/控制留给下一主线。

CHG-20261022-001：核查Excel REQ-051、产品V1.4 §5.2.4、固件V1.1 §4.4/5.1与新版BLE README §6.1/6.2后，移除“未提供validatePassword就拒绝”的门禁。默认保留非空、UTF-8不超过254字节的报文边界，密码原值不trim，不自设8～63位或字符复杂度规则；额外校验器有明确依据时可提供。此修复不补造绑定码、0x8F、Token或超时契约，也不证明开放网络已支持。

## 故障与告警接线（CHG-20261011-007）

通过`createRuntime(..., ..., {events: EventProfileResolver, realtime: DeviceProfileResolver})`接入当前产品事件定义与真实MQTT解码。`events`显式映射已发布事件的标题/等级/文案和恢复事件或属性；`realtime`核验设备身份/实际Topic，返回内部`kind: 'event'`及`DeviceEvent`。内部实例/顺序必须有生产依据，不使用Shadow version/clientToken或App时钟猜测。没有实例/顺序时保留独立上下文，不推断跨事件恢复。

`DeviceSession.events`提供`EventControls`和当前上下文；`DeviceEvents`为UI同事可复用业务组件。关闭/展开仅本地展示；断线/离页未恢复事件待核对，重入保留；新的明确恢复事件或有效属性条件才恢复。Runtime按设备/账号修订隔离，重启不承诺历史持久化。Mock独立`subscribeEvents/emitEvent`通道及Alarm/AlarmRecovered示例只验证业务，不代表生产字段。C-007实际事件载荷、时间/等级、实例/顺序、恢复规则和Topic仍待确认；相关接线及证据的历史资料已移除。
