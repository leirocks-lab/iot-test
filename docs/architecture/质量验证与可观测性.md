# 质量验证与可观测性

[返回架构总览](架构总览.md)

## 验证层次

| 层次 | 重点 | 通过能证明什么 |
| --- | --- | --- |
| 静态检查 | lint、类型、工程结构、依赖及契约 | 源码与配置满足对应规则 |
| 单元与契约测试 | 解析、授权、状态机、事件及取消竞态 | 指定测试输入下的逻辑行为 |
| 原生构建 | Codegen、SDK、资源、链接 | 对应平台和变体可构建 |
| 模拟器或真机集成 | 原生进 RN、查询、返回、账号切换 | 对应安装包的运行链路 |
| 真实设备业务 | 控制、配网、分享、定时、OTA | 对应硬件及服务环境的业务结果 |
| UI 验收 | 蓝湖、字号、主题、语言与异常态 | 对应版本及设备配置的视觉结果 |

各层分别报告。Bundle 导出不等于原生编译；Android 通过不等于 iOS 通过；fixture 和空列表不等于真实写操作通过。

## 必测场景

- 同一设备多观察者：释放一个页面不影响其他使用者。
- 账号切换：旧 HTTP、MQTT、存储写入和桥接回调不污染新会话。
- 事件交错：初始 Promise 前事件、重复、缺序、溢出和晚到快照。
- 重连与恢复：旧 epoch 不覆盖新状态，stale 不呈现为实时在线。
- 页面关闭：旧 pageSessionId 无法关闭后继页面；取消交互返回后仍能正常操作。
- 副作用：超时不冒报成功，不自动重放控制、生成凭据或解绑请求。
- 解绑：原生确认、后台切换、进程恢复、撤权、首页新读及资源清理。
- Release：离线启动、多次进入退出、内存及连接数回收。

双端应复用协议样例与预期结果，分别执行原生测试；共享 RN 测试不能替代两套原生状态机验证。

## 诊断与性能

记录冷启动、进入 RN、首个可用快照、重连恢复和操作确认耗时，并观察主线程阻塞、内存、观察者、连接及订阅数量。性能阈值依据目标设备基线确定，当前不声明统一达标数值。

现有 Android `RnStartupTrace` 提供启动和读取阶段诊断。错误日志只输出脱敏类别及必要关联信息；ANR、超时和网络失败保留对应安装包与环境信息。

## 证据与发布门槛

证据至少关联完整 Commit、构建号、资源 Hash、桥接版本、平台、设备、时间、命令及结果。源码变更后只继承仍有效的结论，历史 APK 结果不得当作新包验收。

当前 Android 和 RN 有历史局部检查及运行证据，iOS 尚缺 macOS/Xcode 编译运行；完整范围和真实硬件仍未验收。最新状态由[实施证据](../测试报告/重构实施-20261101/README.md)和[范围执行状态](../测试报告/重构实施-20261101/范围执行状态.json)维护，不在架构文档复制测试计数。

交付前完成受影响平台的检查、构建、运行和业务验证，单独列出阻塞、限制及未验收项。本次文档整理不改变已有验收状态。
