## 4. 缺陷与代码证据

### D-01：在线标识和控制限制混用 REST 旧状态

- 证据：`src/screens/Home.tsx:93` 用 `device.online !== false` 限制控制；`:114` 直接按 `device.online` 决定圆点颜色。
- 复现：UI-01、UI-04、UI-10。
- 影响：MQTT 已上报在线仍显示离线、开关仍禁用；MQTT 断连后又可能继续显示 REST 缓存中的绿色在线。阻碍 RF-0012-AC-003/004/007。
- 建议修复方向：将已确认实时状态、当前会话可用性和未知/历史状态统一映射至卡片及控制判断；具体在线判定、陈旧阈值继续遵循 C-018 的确认结果。

### D-02：初始连接失败与后续断线信息未呈现

- 证据：`src/screens/Home.tsx:71` 吞掉连接异常；组件只显示 `action.error`，未显示会话的 `error` 或 `controlError`。
- 复现：UI-03、UI-10。
- 影响：用户无法区分设备离线、MQTT 连接失败和能力未配置。

### D-03：无确认状态时呈现关机分支

- 证据：`src/screens/Home.tsx:85` 的 `powered` 在缺少控制能力时回退为 `false`；按钮图标和标签继续按关机渲染。
- 复现：UI-02。
- 影响：未知状态没有明确标识，阻碍 RF-0012-AC-004。

### D-04：发送中缺少独立等待反馈

- 证据：`src/screens/Home.tsx:143` 禁用开关，`:149` 改变透明度，但按钮内部没有发送等待组件或文字。
- 复现：UI-06；UI-05 证明禁用逻辑本身有效。
- 影响：RF-0013-AC-004 的“禁用”部分满足，“等待指示可见”部分不满足。

### B-01：当前部署控制映射缺失，快速开关无法形成真实闭环

- 证据：`src/config/deployment-integrations.ts:13` 只注册 `createClassicShadowResolver()`，未传产品字典，未注册 `contracts.controls`。
- 执行证据：`deployment-integrations.test.ts`、`classic-shadow.test.ts` 断言只读 profile 的 `canWrite=false`、`command` 不存在且无控制映射，相关用例通过。
- 影响：当前本地部署的首页快速开关不可用。通用控制测试成功不表示 `prd_100` 已可控。
- 待核实：物模型标识、Power 值域、Online 字段与在线依据、可写权限和实际部署协议。模拟器中的 `Power=on/off` 只能作为对照材料，不能直接视为全部产品的正式契约。

### B-02：恢复及凭证生命周期仍需专项验证

- `src/protocol/device-session.ts:279` 断线后关闭会话；`Home.tsx` 中重新连接入口主要来自页面聚焦和前台恢复。
- 本次 UI-08 只证明前后台恢复回调有效，未测试持续停留首页时网络恢复、STS 到期前换证、长时间保活或多设备并发。
- 此项不计入 6 个组件失败用例；属于未通过本次验证的范围，不能据此宣称重连及换证已经完整实现。
