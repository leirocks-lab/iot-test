# 分享码原生协议适配

本批继续 S087 的原生服务实现，不调用实际 SHARE-01。用户确认缺少第二测试账号与可恢复隔离设备，分享生成/绑定、成员移除和解绑的真实联调继续[阻塞](真实关系变更联调阻塞-20261102.md)。

## 已实现

Android 与 iOS 增加独立 `DeviceShareCodeRepository` 及 HTTP 适配，使用 V1.4 的 `GET /api/app/devices/{deviceID}/bindCode`。路径以 UTF-8 编码为单段，校验账号及会话归属，响应 `deviceID` 必须逐字匹配目标，`bindCode` 必须为非空字符串。返回对象仅为原生临时凭据，描述与 Swift 调试反射脱敏；不持久化，不发事件，不推断有效期。

SHARE-01 的 GET 会生成凭据，不能因 HTTP 动词而自动重放。双端公共账号服务新增仅限原生调用的 `allowReadReplay` 选项，默认保持既有只读行为；分享生成显式传 false，401 不刷新/重放，超时不重试。普通只读请求仍按已有规则刷新一次。未向 RN 暴露通用 HTTP、Token 或此选项。

这只是协议适配；尚未装配到生产分享入口。调用方仍须通过原生管理员权限、当前设备观察及页面归属校验，不得把 `DeviceMoreScope` 本身当作写权限。分享二维码、原生生成任务所有权、离页释放及 RN 页面尚未完成，不能把本批计为 S087 整行完成。

## 契约与验收缺口

V1.4 要求二维码只保存 bindCode 与必要版本信息，但没有冻结生产二维码的编码结构/版本取值；同时绑定流程要求从扫码取得 deviceID/bindCode。现有资料不足以构造能承诺生产兼容的二维码，不套用旧开发格式。SHARE-01 响应没有 expiresAt/有效秒数或剩余次数，不能自行设定倒计时，也不能把刷新页面等同于明确重新生成。

S088 的单次码绑定、S089 的管理员移除权限与成员关系校验、S087 完整生成/展示生命周期仍继续实施；真实关系变更联调均为阻塞。以上不增加范围表外功能。

本批“禁止重放”证据限定为 App 账号刷新层及显式调用次数；测试替身不证明平台网络栈端到端至多投递一次。启用生产生成入口前仍需完成缓存策略、任务未知结果及生命周期验证，不能据此直接开放真实生成。
