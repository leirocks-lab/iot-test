## 2. 当前设备列表的 MQTT 业务流程

| 步骤 | 发起方与业务动作 | 输入/输出及状态变化 |
| --- | --- | --- |
| 1 | 首页取得设备列表 | `GET /api/app/devices`；真实适配后请求 `/iot/app-api/devices`。取 deviceID、productID、绑定角色等静态信息，REST online 不作为当前 MQTT 在线依据 |
| 2 | 每个可见卡片进入前台会话 | `runtime.createDeviceSession(deviceID)`；页面聚焦、App 前台时 connect，离页或退后台 close；不是账号级聚合订阅 |
| 3 | 获取当前设备临时连接凭证 | DEVICE-01；`GET /api/app/devices/{id}/mqtt`，实际 `/iot/app-api/devices/{id}/mqtt`；校验 deviceID 一致并原值使用 clientID |
| 4 | 连接 MQTT over WSS | STS 分支本地 SigV4 签名，交给 MQTT.js；连接成功事件后才继续。请求订阅 QoS 1；发布 QoS 1、retain=false |
| 5 | 加载设备与产品能力 | DEVICE-02 + thing-model；Controlled wrapper 和同步会话各读取上下文，因此本轮轨迹中详情/物模型请求出现两次。可选物模型错误不伪造能力，而以空模型继续只读同步 |
| 6 | 按序订阅四个精确 Topic | 每个等待 SUBACK；全部成功后才发布状态查询。拒绝、超时或取消不会假装已订阅 |
| 7 | 发布 Shadow GET | 向 `/shadow/get` 发布 **0 字节载荷**，不是 JSON `{}`；等待 `/get/accepted` 的有效全量文档，不能凭 PUBACK 标记 ready |
| 8 | 应用全量 reported | `state.reported` 经解码进入 confirmed；设置 ready=true。desired 和 delta 不直接当成已执行状态；保留 version 供去重排序 |
| 9 | 持续接收属性变化 | `/update/accepted` 中的 reported 合并至 confirmed；已就绪后忽略 version 小于或等于当前版本的上报 |
| 10 | 卡片渲染与控制限制 | 使用协议映射后的 session.online；未同步、断连、映射缺失或未知值时显示“状态未知”。未知电源显示 `?`；错误可见，发送中禁用并显示等待指示 |
| 11 | 有正式控制能力时下发 | 检查实时在线、Power 映射、权限、当前值和等待状态后，发布 Shadow desired；当前真实部署缺少映射，停在能力限制，不实际下发 |
| 12 | 等待真实确认或结束 | 控制需匹配本次 clientToken 的 desired acceptance，再观察更高版本且值匹配的 reported；10 秒未确认显示“未确认设备结果”，不自动重发。退后台/离页关闭资源 |

源代码：`src/screens/Home.tsx`、`src/services/runtime.ts`、`src/protocol/device-session.ts`、`src/protocol/controlled-session.ts`、`src/protocol/classic-shadow.ts`、`src/protocol/mqtt-browser.ts`、`src/protocol/mqtt-auth.ts`。

## 3. Topic、方向和数据格式

以下 `{id}` 在真实联调中为 `dev_666666`。

| Topic | App 行为 | 消息用途 |
| --- | --- | --- |
| `$aws/things/{id}/shadow/get/accepted` | SUBSCRIBE | 全量影子，读 `state.reported`、`version` |
| `$aws/things/{id}/shadow/get/rejected` | SUBSCRIBE | 查询失败，包含 `code`/`message`，GET 可没有 clientToken |
| `$aws/things/{id}/shadow/update/accepted` | SUBSCRIBE | desired 接受通知或 reported 上报，必须区分处理 |
| `$aws/things/{id}/shadow/update/rejected` | SUBSCRIBE | 写请求失败；控制时按 clientToken 关联请求 |
| `$aws/things/{id}/shadow/get` | PUBLISH | 本轮真实发送一次，载荷 0 字节 |
| `$aws/things/{id}/shadow/update` | 有控制能力时 PUBLISH | `{state:{desired:{...}},clientToken:...}`；本轮真实连接没有发布此 Topic |

**当前 App 只订阅上面四个响应 Topic。** 不订阅 `/update/documents`、`/update/delta`、`LF-WM05/{id}/connect`、`mcu/version` 或 `callapi/Resp`。用户设备模拟器的固件 Topic 与 App 的 Shadow Topic 是不同角色，不能用模拟器的两个 SUBACK 代替 App 的四个订阅验收。

查询/更新错误会通过标准解码处理，例如 `{ "code": 404, "message": "..." }` 的 GET rejected 使会话提示影子尚未创建；本轮真实 GET 成功，没有实际收到 rejected 报文。错误处理证据来自现有单元测试，不列为真实服务器本轮回包。

解读：

- reported 的真实确认值是 Power=on、TargetTemp=10；desired 中的 off/14 不能当作实际执行结果。当前快照没有收敛到这些期望值；本轮没有再次发送它们，也不从单张快照推断历史设备行为的根因。
- `metadata.reported.Power.timestamp=1793030020`、Online 同值，换算为北京时间 **2026-10-26 23:53:40**；TempCurrent 最近时间 `1793030230` 为 **23:57:10**。GET 响应时间为次日 **07:57:15**，属性值已约 8 小时没有相应时间戳更新。
- 响应顶层 timestamp 是本次响应时间，不能代替各 reported 属性的更新时间；`Online="online"` 也是影子存储值，不能单凭字符串宣称设备当前在线。当前需求中的在线有效性及陈旧阈值仍需要 C-018 的契约依据。
- 本轮不修改设备 reported、desired、证书、Policy 或数据库；`MockTest` 是已有影子字段，不是本轮 App 生成的模拟数据。
