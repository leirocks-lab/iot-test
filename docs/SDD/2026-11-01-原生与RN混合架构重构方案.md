## 2. 原生与 RN 职责边界

| 模块 | 页面归属 | 服务归属 |
| --- | --- | --- |
| 启动、登录、注册、找回密码、地区及协议 | 原生 | 原生账号、配置和内容服务 |
| 首页、房间分组、设备卡片、快捷开关 | 原生 | 原生设备状态和命令服务 |
| 添加入口、产品列表、扫码、蓝牙发现 | 原生 | 原生产品、扫码及发现服务 |
| Wi-Fi 输入、配网进度、绑定、昵称及结果 | 原生 | 原生配网状态机与协议驱动 |
| 我的、房间管理、用户偏好及全局设置 | 原生 | 原生业务服务 |
| 设备控制、实时状态、模式、维护提示 | RN | 原生设备会话和命令服务 |
| 设备更多、设备内分享、定时、固件升级 | RN | 原生业务、权限及升级任务服务 |
| 权限、安全存储、推送、深链、第三方 SDK、文件 | 原生 | 原生平台服务 |
| 设备页面资源更新 | 原生管理器；RN 展示设备业务 | 服务端发布与资源分发协同 |

设备子流程进入房间选择、系统设置等全局能力时，通过桥接打开原生页面并获取结果。设备解绑成功后，原生清理对应会话、关闭相关 RN 流程并刷新首页。分享二维码展示可在 RN，系统分享与扫码能力由原生承接。

全局导航和设备入口由原生控制。RN 只负责设备子流程内部导航；不得由 RN Router 接管首页、添加、配网和我的。设备标题栏和返回行为由宿主与 RN 契约统一，避免重复导航栏和返回栈。

“设备页资源热更新”和“设备 MCU/Wi-Fi 固件 OTA”是独立系统：两者分别维护版本、任务、错误及回滚语义。RN 固件升级页面只展示并操作原生管理的升级任务。

## 3. 现有工程评估

当前基线：Expo `~57.0.27`、RN `0.86.3`、React `19.2.3`、TypeScript、pnpm；入口为 `expo-router/entry`。本轮不升级依赖。

迁移后的关键位置：

| 文件或目录 | 当前职责 | 后续改造 |
| --- | --- | --- |
| `app-rn/src/app/_layout.tsx` | 全 App 路由及认证保护 | 全局导航迁至原生，仅保留设备内部流程 |
| `app-rn/src/ui/context.tsx` | 全局 AppProvider 和运行时 | 改为设备模块上下文及原生适配 |
| `app-rn/src/services/runtime.ts` | 账号、BLE、配网、设备会话装配 | 拆至原生服务与 RN 适配接口 |
| `app-rn/src/screens/Home.tsx` | 首页、设备会话及快捷开关 | 页面重写为原生，使用统一设备服务 |
| `app-rn/src/screens/Device.tsx` | 设备 UI，依赖全局服务和路由 | 保留可复用 UI，替换全局依赖 |
| `app-rn/src/services/onboarding.ts` | 配网编排、绑定、超时及状态机 | 迁入原生配网服务 |
| `app-rn/src/protocol/` | BLE 两条路线、MQTT、Shadow 等 | 保留契约及测试向量，迁移执行层 |
| `app-rn/src/services/native-storage.ts` | JS 侧安全存储适配 | 登录态所有权迁至原生 |

当前首页也依赖 RN runtime 提供设备状态和控制，不能只迁移页面。BLE 库最终调用原生，不等于完整配网业务已经原生化；协议、状态机、取消和绑定编排仍需迁移。

可复用资产：设备 UI、图片、主题令牌、物模型、控制映射、接口语义、协议测试向量与已有测试经验。TSX 不能直接变成 Swift/Kotlin 原生页面。现有测试通过不代表物理模组、云端和双端原生闭环已验收。

## 4. 方案比较与推荐选型

| 方案 | 优点 | 代价及约束 |
| --- | --- | --- |
| 原生主工程 + 直接嵌入 RN，按需保留 Expo 模块 | 原生主导、职责清楚，可控制容器和动态装载 | 需建设容器、桥接、发布和兼容机制 |
| 原生主工程 + Expo Brownfield | 可利用 Expo 嵌入及双向通信工具 | 官方总览标记集成支持为 alpha，需验证兼容性和更新链路 |

推荐第一种，作为待验证的实现基线；用户已确认混合架构与页面边界，尚未冻结具体容器实现。Expo 不必一律移除，但不得继续作为全局页面入口。以当前版本作为技术验证候选，不同时开展无关的大版本升级。

- Android 建议 Kotlin + Jetpack Compose。
- iOS 建议 Swift + SwiftUI/UIKit。
- RN 设备模块使用 TypeScript，跨端共享页面、组件和产品适配。
- 通信优先评估与所选 RN 版本匹配的 TurboModule/Codegen；不依赖旧桥接 API 记忆直接实现。
- 单仓库维护三部分源码；目前仅 `app-rn/` 有 Node 应用，不新增根级 package.json 或 JS 工作区。

未来具体版本、最低 OS、JDK、Xcode、Gradle、CocoaPods/SPM 和第三方 SDK 通过双端集成验证后锁定。任何依赖变更需阅读匹配版本的官方文档。

## 5. 服务与桥接设计原则

### 5.1 原生服务统一所有权

原生负责 Token、安全存储、刷新、退出及租户切换。RN 通过受控业务接口获取数据，避免双套登录态、重复刷新和旧账号回调污染。

原生管理 MQTT 凭证、连接、订阅、Shadow 快照及设备命令。首页和 RN 设备页消费同一服务。连接复用粒度依云端凭证、Client ID 和 Broker 限制决定，不预设所有设备必须共享单连接，也不允许两个页面独立争抢会话。

配网的扫描、BLE 握手、Wi-Fi 参数、认证激活、绑定轮询、超时、取消和恢复由原生管理，兼容现有 `0x0822`、`0x0922` 已确认契约。保留测试向量，先迁移再以真实手机、模组和云端验证。

### 5.2 版本化接口

桥接至少覆盖宿主上下文、设备元数据/物模型、状态快照与订阅、控制命令、定时、分享与成员、设备设置/解绑、固件升级任务、原生页面打开和关闭。

接口携带设备标识、请求 ID、会话修订、版本、取消/超时和统一错误信息。具体签名写入后续桥接 SDD 后冻结，不将本文能力列表视为已实现 API。

原生校验权限、设备归属、物模型和参数范围；服务端保留最终鉴权。事件需可取消订阅、去重和恢复，旧会话回调不得更新新账号页面。用户偏好中的语言、主题、温度单位通过宿主上下文统一传入，并在变化时同步。

命令发送成功、Shadow desired 被接受与设备执行成功应区分；最终 UI 依据真实 reported/任务结果确认。重连恢复订阅并读取快照，不自动重放未确认控制或一次性维护动作。

### 5.3 生命周期

原生宿主管理 RN runtime、页面实例和资源版本。处理进入退出、前后台、账号/租户切换、解绑、内存压力及异常。页面退出释放页面订阅，不能误关首页仍使用的会话。

首版优先一次运行一个已选设备 Bundle；同 Bundle 切换设备可复用 runtime。切换不同完整 Bundle 时销毁并重建相应 runtime，不能把独立 Metro Bundle 当普通模块随意拼接加载。是否预热依据实测启动耗时和内存决定。

公共业务尽量复用 API 契约、物模型、产品配置、测试向量和 RN 组件；原生 UI 与平台驱动允许各端实现，不承诺两种语言共享全部代码。暂不引入额外跨端业务框架。

## 6. 设备组件与产品适配

共享组件覆盖甲方要求的开关、滑杆、模式、档位、定时、曲线及故障提示；仅在已确认产品能力和业务范围内启用。已有范围未授权的历史曲线接口、全局消息中心或其他业务，不因组件要求自动新增。

建立产品 ID/版本、物模型版本、能力标识与 RN 控件的映射。权限、可写性、枚举、单位和数值边界来自明确契约，不按图片或产品名猜测控制字段。未知物模型、未知枚举及不兼容配置应显示明确状态并阻止错误控制。

## 7. 动态资源发布与装载

### 7.1 首版资源粒度

推荐完整设备模块 Bundle + 产品映射配置，按平台及兼容运行时构建。一个 Bundle 可覆盖多个产品，服务端按产品和产品版本返回匹配资源。是否要求产品独立发布尚待甲方确认；需要时按产品族发布完整 Bundle，避免首版引入多包依赖拼接。

### 7.2 Manifest 与兼容矩阵

签名 Manifest 至少描述资源 ID/版本、平台、产品及硬件/固件适配范围、App 版本范围、RN/JS 引擎运行时标识、桥接版本、IoT SDK 版本、物模型及 API 契约兼容范围、资源地址、大小、文件 Hash、签名标识、发布时间、源码 Commit 和撤回状态。

壳层应在执行资源前校验整个兼容矩阵。App 版本号相同不代表原生能力相同。RN 引擎、原生依赖或新桥接能力不能通过 JS 包补齐，必须发布新的宿主应用。

### 7.3 加载流程

1. App 启动可后台检查；进入设备页根据设备/产品信息再次解析目标版本，不强制每次进入都等待网络。
2. 优先使用本地已校验兼容版本，按策略下载候选资源。
3. 通过 HTTPS 和可信来源下载，校验签名 Manifest、文件 Hash、大小、完整性及解包路径。
4. 完整校验后原子安装，标记待验证版本；在下次进入等安全时机激活，不替换用户正在操作的 runtime。
5. 候选版本成功启动并满足健康条件后标记可用；失败则隔离候选，回退兼容的最近可用版本或包内默认版本。

Hash 不能证明来源，必须结合可信签名；公钥及轮换策略由宿主管理，签名私钥仅存在受控发布环境。历史坏版本和已撤回版本不得无限重试或被错误回滚重新启用。

### 7.4 缓存、故障与发布治理

- 本地维护包内默认版本、最近已验证可用版本、待验证候选版本；清理缓存不能删掉必要兜底。
- 弱网、断网、超时、资源损坏、不兼容、JS 异常和启动崩溃分别记录并恢复；不能只依赖 JS try/catch，应由原生通过启动标记识别失败候选。
- 离线可用指页面资源可加载；依赖云端的设备控制是否可用由实际通信能力决定，不承诺新增本地控制通道。
- 灰度使用稳定分组，支持暂停、撤回、回滚和最低 App 版本限制；强更断网时是否允许兼容回退需冻结明确策略。
- 灰度、下载、加载、崩溃和回滚记录应关联资源版本及宿主版本，记录脱敏，不上传 Wi-Fi 密码、Token 或设备秘密。

服务端需提供版本解析、产品映射、兼容查询、资源存储/CDN、受控签名发布、灰度、撤回和记录查询。发布后台是否新建 UI 或复用既有平台需明确范围；不能仅靠客户端闭环。

EAS Update 可评估为更新基础设施，但不能替代全部产品版本映射和发布治理；不默认绑定某个商业热更新服务，也不承诺 Expo Brownfield 的所有更新能力可直接使用。

## 8. 商店审核适配

Apple 2.5.2 对下载执行引入或改变功能的代码有限制；Google Play 限制外部可执行代码，并要求运行时加载的解释型代码符合政策。技术上可加载不等于审核必然通过。

动态发布限定在已审核设备能力范围，明确目标商店和分发渠道；新增原生能力及超出允许范围的功能通过商店版本发布。保留包内设备资源和商店发布路径，不隐藏功能或使用审核绕行逻辑。具体渠道策略、审核材料和功能变更边界需单独评审。

## 9. 目录与工程管理

```text
rowan-iot-app/
├─ docs/                 原始资料、业务范围、SDD、验收证据
│  └─ SDD/               架构、契约、兼容及实施设计
├─ android-as/           正式 Android 原生宿主源码
├─ ios-as/               正式 iOS 原生宿主源码
└─ app-rn/               现有 Expo/RN 工程，逐步收敛为设备模块
   ├─ src/
   ├─ assets/
   ├─ scripts/
   ├─ tests/
   ├─ app.config.ts
   ├─ package.json
   └─ pnpm-lock.yaml
```

根目录保留 Git、编辑器、规则、许可证及 README。本机缓存和依赖不属于正式业务目录，不纳入交付。

`android-as/`、`ios-as/` 未来是人工维护并提交的原生宿主，不能由 Expo prebuild 覆盖。当前 `app-rn/android/`、`app-rn/ios/` 若存在，仍是旧 Expo 验证工程的生成目录，不是正式宿主。RN 保留旧页面作为迁移基线，完成对应原生功能验收后再删除。

RN 安装、运行和检查从 `app-rn/` 执行。根规则和 README 必须随架构更新；历史文档保留原结论，迁移路径链接可修正，历史命令需按新目录解释。

## 11. 源码交付与验收

交付双端原生工程、RN 业务、配网、桥接、设备组件、品牌资源、配置模板、依赖锁定、工具链版本及构建/资源发布/回滚脚本。内部组件需随源码交付或确保甲方拥有独立持续访问权限。

验收版本关联源码 Commit、App 构建号、Bundle 版本、资源 Hash、签名标识和发布时间。甲方可在规定环境依文档构建对应验收版本；不承诺签名和时间戳导致的安装包逐字节一致。

私钥、证书凭据及后台秘密通过甲方控制的凭据渠道管理，不写入仓库。双端构建、首启、登录、配网、控制、定时、分享、升级、解绑和账号切换需提供实际证据。Windows 不能代替 iOS 的 macOS/Xcode 构建和真机验证。

## 12. 范围差异及待确认事项

现有范围表未单列设备页动态发布、签名、灰度、回滚和兼容平台能力。进入相关实现前，将新增技术交付项和责任纳入范围依据并获得明确授权；本次不修改 xlsx。

当前 Store 仅占位，Mine 的未冻结业务、未知曲线来源、消息中心等不能借架构重构自动新增。

后续需要冻结：

1. 是否要求每个产品独立发布 Bundle，还是允许完整设备模块 + 产品配置。

5. 强更遇到断网、坏包及不兼容时的允许操作和回退策略。
6. 开发人员、甲方构建环境、发布权限及按双端重写重新估算的排期与工作量。
