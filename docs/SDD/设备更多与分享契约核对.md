HTTP、产品功能与交互依据[V1.4](../prd/ROWAN公共App产品功能及API详细设计说明书_V1.4.docx)。本文¶按DOCX `word/document.xml`全部`w:p`顺序从1计数，包含表格，不是页码；旧代码行号为本次核对时的位置。

## 3. 角色、数据与业务规则

### 设备身份与元数据

每个方法引用当前原生观察/页面持有的账号修订和设备上下文；通过fresh归属校验后才调用功能仓库。每次请求将同一意图的expectedRevision传入AccountService原子检查，返回后复核账号与设备/页面，不使用新账号Token执行旧意图。读取产品模型版本不是这些元数据功能的前置条件，不填假的modelVersion，也不因控制字典缺失阻塞昵称、房间、帮助或成员读取。

DEVICE-02的静态online字段不作为实时在线确认。资料缺失、未知角色、错误/超时不得补造姓名、邮箱、房间、设备在线或操作成功。

### 成员与管理员操作

V1.4 ¶2170、2237定义sa管理员、mbr普通成员、obs观察员；obs不统计进设备成员中。S087明确管理员生成分享码，MORE-03 ¶2281明确管理员解除**普通成员**绑定。不能把此操作扩大为删管理员、观察员或任意userID；不能从用户显示名、列表顺序、category或App角色标签推断权限。

成员列表应保留缺失nickname的关系项，使用不暴露联系方式的通用显示；不把email/mobile作为昵称fallback，不将后台原始联系方式传入普通RN列表或日志。MORE-01示例¶2243出现同userID两项角色不同，不能据此实行last-wins或误删；应将重复/冲突身份记为无效或歧义，禁止关系修改，待权威列表核对。

除上述明确的管理员分支，MORE-04/ROOM-01/MORE-05等详章没有给出完整sa/mbr/obs操作矩阵。服务端是最终权限判断者；不得沿用旧代码的泛化“不是obs就都能写”作为正式授权。权限未知的敏感修改保持不可用，读请求仍核验原生归属和HTTP授权。

### 昵称

MORE-04只接收nickname字符串，不写deviceNickname、产品名或整份DEVICE-02对象。S057和V1.4 ¶435给绑定后昵称0–20字符、跳过使用产品默认名的流程；“跳过不提交”与“PATCH空字符串”不是同一契约。当前空串重命名的结果、字符计数方式仍须核对，不能从旧实现非空检查推导所有场景，也不能把修改失败当作跳过成功。上限和输入状态按当前范围与设计图处理；未确认分支应说明限制。

### 房间

ROOM-01参数表¶2381–2384写Number、必填，但同一说明允许省略/空值解除，示例¶2402及响应使用String；ROOM-02 ¶2436–2438也有Number/字符串示例差异。现有策略保留ROOM-03实际返回的string/number原始类型，解除归属以省略id构造空body，不新增DELETE路由或null值。

当前房间与候选列表分别读取；未返回默认房间、数量、版本等时不造值。S085是移动设备归属，不授权删除房间或迁移房间内真实设备。更多页调用既有原生location/move入口；目标消失、权限变化或读回不同需显示当前权威状态，不能停在虚假的已移动。

### 帮助

MORE-05的type参数说明出现“用户协议”字样，但章节、返回标题与实际响应均为设备帮助，不能请求成隐私政策。正文必须来自该设备授权响应，空数组可展示暂无帮助；缺data、错误类型或拒绝响应不能变空成功。

text与url展示区分；链接必须先经原生受信策略核验，不能执行javascript/file/content/intent等任意scheme或任意HTTP路径。受信帮助来源/URL策略未给时可优先显式请求type=text；不能把任意响应网址交给RN直接打开。S090不等于新增PRODUCT-02/03、HELP-01/02完整帮助中心。

## 4. 分享生成、二维码与绑定的未冻结项

SHARE-01使用GET但会生成短期绑定凭据。它不是普通可自动重放读取：进入更多/成员列表、页面重渲染、后台恢复、401续期或网络自动重试都不能隐式生成新码。必须由当前管理员的明确操作触发，原生按设备/账号维持在途与未知结果状态，避免双击和重挂载绕过限制。

当前AccountService普通GET的401刷新重试语义不能直接用于SHARE-01。后续需要独立的“不重放生成请求”调用策略/原生入口；不能在RN绕开账号服务自行发HTTP，也不能为绕过GET重试偷偷改成POST。

| 项目 | 正式依据及缺口 | 实施边界 |
| --- | --- | --- |
| expiresAt | 公共ShareBinding模型¶712–715列出字段；SHARE-01详章未定义其类型、单位、缺省、服务器时间与时钟偏差 | 原值/缺失按未确认处理，不按数值大小猜秒/毫秒，不强制旧ISO形状为所有部署契约 |
| 二维码格式 | ¶2716要求短有效期、限制次数、只存bindCode和必要版本信息、不存accessToken；S087需要设备/码身份，S039有deviceId/productId/bindCode解析 | JSON/URL/二进制、版本、字段拼写和设备身份携带方式没有完整冻结；不能造可扫码生产码 |
| 使用次数与结果 | ¶2003明确bindCode单次有效；1133不区分不存在与过期的细分编码 | 扫描去重，同一次消费最多派发一次；不能后台重试消费或把失败改成绑定成功 |
| 绑定角色 | PAIR-06返回bindingRole；首次绑定者为sa | 被分享用户的角色由云端确定，不在body指定mbr或sa，不从扫码文案授予角色 |
| 码生成结果丢失 | 没有已生成码发现/恢复/撤销接口 | 保持生成未知，不自动再GET；缺少幂等/恢复契约时不能声称完全恢复流程可用 |
| 分享发送 | 这组接口没有邀请发信/短信/通讯录发送契约 | 生成/展示二维码不等于发送消息，本轮不向别人发消息或自动调用外部分享渠道 |

二维码编码/到期契约缺失不阻塞授权、typed HTTP端口、错误与未知结果状态、原生假数据测试和已确认UI状态结构；实际可扫码展示/消费闭环仍应标为待确认/未验收。

## 5. 状态、取消与unknown/no-replay

| 操作 | 确认路径 | 结果不明/取消后的处理 |
| --- | --- | --- |
| 读取详情/成员/房间/帮助 | 真正GET业务成功并解码，账号/观察仍有效后发布 | 读取可显式重试；保留同账号最近确认值并标陈旧，越权或切账号清除可见私有数据 |
| 昵称保存 | PATCH公共成功，再GET DEVICE-02核对目标昵称，同步原生首页/设备权威状态 | 派发后超时/取消/坏回包保持unknown；只GET核对，不自动PATCH重放；读回不同不能假成功 |
| 房间修改 | ROOM-01，再ROOM-02确认真实归属 | 保留旧确认值；目标缺失/读回失败继续unknown；不重复PUT作为补偿 |
| 成员移除 | 当前设备管理员+普通成员关系确认；DELETE后MORE-01核对目标消失 | 取消确认对话不请求；派发后未知不自动DELETE；目标仍在/读取失败继续unknown；1372刷新角色，1373核对最新关系 |
| 自解绑 | 明确说明是解除自己的绑定；DELETE成功后释放该设备观察/订阅/缓存并刷新HOME | 丢响应后用HOME关系核对，不以失败的HOME当作“不存在”；确认解除后才统一清理，未知不重发DELETE |
| 分享生成 | 管理员明确触发，不重放GET；完整结果与冻结到期/格式校验后进入可展示状态 | 本地取消等待不撤销已生成码；旧账号/旧generation返回丢弃；恢复策略未定义时保留unknown |
| 分享绑定 | 用户明确确认目标；PAIR-06成功身份/角色一致，再刷新HOME/详情 | 本地取消不撤销服务端已消费码；若响应丢失，不重发同码；读取关系可说明已绑定状态，但不伪造码消费的因果证据 |

所有未知操作的本地标记应由未来原生application owner持有，不能随RN页面卸载重建而自动消失。跨进程恢复与持久化另需实际实现/测试；敏感bindCode不写普通偏好、报告或日志。页面关闭、后台、取消协程仅结束本地等待，不构成服务端撤销或事务回滚。

S032首页多选删除复用逐设备MORE-02；逐项保存成功/失败/未知，部分失败保留对应设备，不能全批显示成功，也不新增批量删除云接口。清理限于当前账号当前设备的授权资源，不能关闭其他页面/设备共享连接。

## 8. 下一批最小实施分解

1. **原生设备更多读取层**：每次fresh授权与expectedRevision；独立typed DTO读取设备摘要/角色、成员、帮助；安全投影不携带mac、联系方式、原始JSON、凭据或任意URL。桥接保持观察句柄绑定和固定错误。
2. **原生昵称与成员修改服务**：按设备/账号持有单一workflow，typed nickname/已核对成员目标，不提供任意payload；提交前校验原生权限与当前关系，取消/错误/unknown/no-replay，GET核对后更新权威状态。昵称空串和未冻权限分支明确阻塞。
3. **房间适配复用**：复用已存在DeviceRoomRepository；补路径边界与更多页安全投影/选择契约，保opaque ID；不在本批重建房间CRUD或猜CAS字段。
4. **自解绑application owner**：设备关系操作意图、未知结果及逐项批量结果由原生持有；确认解绑后统一释放观察/订阅/缓存并刷新首页。释放一个设备不影响其他设备共享broker连接。
5. **分享原生端口与状态**：先实现非重放生成/消费策略、角色/设备守卫、单次在途与错误模型，所有凭据memory-only及redacted；二维码格式/expiry契约未补前不假造生产可扫码结果，不发消息。
6. **RN页面**：更多→昵称、房间、成员、设备帮助、自解绑确认；后续分享页面根据native能力/状态显示生成、失效、不可用或unknown。页面不自持账号/HTTP，不自行推断授权；写方法需专门版本化契约，不能把只读itemKey升级成写授权。
7. **先行为测试再接线**：精确method/path/body/response；GET数组与无data mutation；scope/expectedRevision；dotsegment零dispatch；重复/未知角色；403/业务错误；派发前取消零写、派发后取消unknown；丢响应仅GET核对；生成GET和消费PUT均不重放；关系清理只发生于确认结果且不影响其他观察。

正式缺口继续保留：二维码编码/版本/身份携带方式、expiresAt类型单位与时钟规则、生成未知恢复/幂等契约、昵称空串语义、未明确的元数据修改角色矩阵、未分配房间的完整响应形状及帮助URL信任来源。上述缺口不授权新字段、新接口、消息发送或虚假验收。
