# 原生页面关闭与桥接V3

这是宿主与内置RN同步实施的破坏性契约修订，当前主版本为3。此前major2报告、截图和安装包保留原结论，不作为V3验收证据；不要求旧内置包与新宿主混用，也没有启用远程RN发布。

## 触发与行为

Android/iOS都可能在多个原生设备页间复用RN runtime及TurboModule。原零参数`closeDevice()`只能找到当前页，旧A页的迟到调用可能关闭后打开的B页。账号相同、设备相同或module owner相同均不足以证明关闭意图属于B。

每个原生设备页实例创建独立随机`pageSessionId`，与deviceId一起作为RN初始props传入。令牌仅用于原生页面关闭，不是业务设备ID、登录凭据或HTTP参数，不记入日志/报告正文。

`closeDevice(pageSessionId:string):void`只在令牌精确匹配当前原生设备页、该页与账号上下文仍有效时关闭。旧页、空令牌、已退出或失效页面均不关闭后继页面。令牌来自调用页面初始props，不能在点击时从最新全局getContext/module映射获取；没有观察句柄或启动失败时，仍可凭本页原生令牌正常返回。

RN仅接受`getContext().bridgeMajor===3`，major2明确不兼容。本轮方法名称仍13个，closeDevice签名变更；既有13字段设备快照、六个只读功能摘要、精确ACK和HTTP/MQTT依据不变。Android、Swift、ObjC++、TS及测试必须同步。

## 验证边界

回归覆盖A创建关闭意图→A离开/B替换→迟到A关闭不得影响B、B自己的合法关闭、缺少令牌/账号失效拒绝，以及无observe时的本页返回。纯策略/调度测试与实际双页runtime测试分别记录，不以JVM或TS测试替代模拟器/Swift运行。

V3新包尚待构建及模拟器验收，iOS仍缺macOS/Xcode。既有设备更多、未绑定业务码、在途返回和句柄撤权守卫保持；普通失联允许重新核验HTTP，FORBIDDEN/Closed观察不能返回私有摘要。
