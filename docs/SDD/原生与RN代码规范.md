# ROWAN 原生与 RN 代码规范

日期：2026-11-01。适用目录：`android-as/`、`ios-as/`、`app-rn/`。

依据：用户提供的《A 类 App 技术架构要求》截图、已确认的页面边界及仓库 AGENTS.md。本文规定后续实现和评审标准，不表示原生宿主、桥接或动态发布系统已完成。截图中的报价条款不属于代码规范或完成证明。

## 1. 依据、范围与当前状态

- 业务范围仍以仓库规则指定的唯一范围表为准；规范和设计稿不能授权新增业务。
- HTTP 接口及 App 功能、页面、流程参考 [V1.4](../prd/ROWAN公共App产品功能及API详细设计说明书_V1.4.docx)。
- 仅 MQTT 参考 [V1.6 Corrected](../prd/ROWAN_AS_App_Spec_V1.6_Corrected.docx)。交叉约定有冲突时记录差异并确认，不直接覆盖。
- 视觉参考 [蓝湖地址](../ui/蓝湖地址.txt)，本地导出图辅助核对。无法访问或版本不一致时记录未确认参数。
- 当前 `app-rn-old/` 保留完整旧工程作为业务理解和结果对照资料；`app-rn/` 仅建立新模块目录和规则，原生目录尚未建立正式宿主，不以目录存在代表实现完成。
- 重构以已确认业务流程、协议语义、视觉要求及最终可观察结果一致为目标。旧代码不约束新架构、接口形态、状态机、导航、依赖或代码组织；可重新设计或重写，不要求逐文件搬迁或保留旧接口。
- 一致性验收覆盖正常流程、失败/取消/恢复、权限、账号与设备状态、控制结果及任务最终结果；测试优先断言这些业务行为，不照搬旧实现的调用顺序和内部结构。旧代码缺陷不作为必须保留的行为；与正式依据有冲突的旧行为记录差异并确认。
- 当前唯一范围表在工作区缺失，进入逐项业务实施前须恢复或确认其正式位置；不得自行将另一份范围表当作等价替代。
- 动态资源发布、签名、灰度、回滚及服务端发布治理先记录技术要求；按现有范围规则确认并补齐授权后实施，不以本文作为新增范围授权。

## 2. 目录与依赖方向

| 位置 | 允许职责 | 禁止事项 |
| --- | --- | --- |
| `android-as/` | 正式 Android 宿主、原生页面、平台与业务服务 | 由 Expo prebuild 覆盖源码 |
| `ios-as/` | 正式 iOS 宿主、原生页面、平台与业务服务 | 由 Expo prebuild 覆盖源码 |
| `app-rn/` | 共享设备子流程、组件、产品适配、宿主接口适配 | 在最终设备模块内重新持有账号和连接 |
| `app-rn-old/` | 旧 Expo/RN 应用、迁移对照及测试向量 | 将旧全局 runtime 整套复制到新模块 |
| `docs/SDD/` | 架构、契约、兼容矩阵、工具链、验收记录 | 将设计草案写成已验收结果 |

目标依赖方向：页面 → 用例/状态模型 → 服务接口 → 平台或协议适配器。平台 SDK 调用集中封装，不散落在页面中。设备业务接口不得反向依赖页面或 RN runtime。

各端内部采用功能模块组织；业务、数据传输、存储、平台驱动与 UI 分开。首版不为目录整齐强制创建多 Gradle 模块、Swift Package 或新 JS 工作区。具体物理模块在实施设计中确定。

## 3. 原生与 RN 职责

- 原生负责启动、账号、首页、添加设备、扫码、BLE/Wi-Fi 配网、我的、房间、全局设置及全局导航。
- RN 负责设备控制、更多、设备内分享、定时与固件升级页面，以及这些页面的展示状态和内部导航。
- 原生负责 Token、安全存储、HTTP、MQTT、BLE、权限、推送、深链、第三方 SDK、升级任务及 RN 容器生命周期。
- RN 通过业务接口读取数据、订阅状态并发起动作；不得自行创建生产 HTTP/MQTT/BLE 通道，也不得持久化第二套登录态。
- RN 请求房间选择、系统分享、权限设置等全局能力时调用宿主接口。退出设备流程由宿主关闭容器，内部返回由双方约定，不出现重复标题栏或返回栈。
- 共享 RN 组件、产品映射、接口语义与测试向量；原生 UI 和平台驱动按平台实现。不得因截图要求复用而擅自改变已确认的原生页面边界或引入新的跨端框架。

## 4. 语言、命名与代码组织

| 部分 | 约定 |
| --- | --- |
| Android | Kotlin 为默认语言；类型用 PascalCase，函数/属性用 camelCase；UI 不直接调用 SDK，异步任务有明确所有者和取消路径 |
| iOS | Swift 为默认语言；类型用 PascalCase，函数/属性用 camelCase；UI 更新在正确执行上下文，跨任务共享状态有明确隔离策略 |
| RN | TypeScript；组件用 PascalCase，自定义 Hook 以 use 开头；外部数据先校验，禁止用无约束 any 绕过契约 |
| 公共契约 | 字段、枚举、时间格式、单位和错误码统一；保持后端正式字段语义，平台命名差异在适配层转换 |

- Android UI 候选为 Compose，iOS 为 SwiftUI/UIKit；在双端技术验证后冻结，不将候选技术写成已交付依赖。
- 导出接口和复杂状态机说明用途、所有权、失败及取消语义。注释解释约束与原因，不重复描述语句。
- 金额、温度、时间和百分比使用显式单位及转换；禁止页面各自猜测倍率、时区或取值范围。
- 异步返回显式区分成功、失败、取消与执行结果未知；禁止空 catch、无限重试、吞错或用固定延时表示业务完成。
- 复用现有格式化与静态检查配置；原生格式工具随工具链验证引入并锁定，不在本文中假定已配置。

## 5. 桥接契约

- 桥接方案先以锁定 RN 版本做双端技术验证，再冻结详细接口；不直接套用旧桥接示例。
- 公共契约在 SDD 维护单一语义定义，并对应 TS、Kotlin、Swift 类型；变更同时更新两端适配及契约测试。
- 最小能力覆盖宿主上下文、设备资料、物模型、状态快照/订阅、控制、定时、分享、设置/解绑、升级任务及原生页面打开/关闭。
- 请求关联请求 ID、设备标识、会话修订和契约版本；有明确超时、取消与错误返回。具体字段名在桥接设计中冻结。
- 事件包含设备和会话上下文、观察标识及修订依据；快照捕获与原生观察建立须有一致性保证，RN 先监听并缓冲，再应用快照及后续有效事件，避免读取快照与订阅之间丢失更新。详见 [架构及通信设计](原生与RN架构及通信设计.md)；处理重复、过期、缺失和缓冲溢出时的重新同步。
- 订阅返回可释放句柄；页面卸载、解绑、退出账号及 runtime 销毁必须清理。页面退出不得误关其他页面仍使用的设备连接。
- RN 不接收长期 Token、MQTT 密钥或 Wi-Fi 密码用于自行通信；原生在服务边界校验设备归属、权限、能力和参数，服务端保留最终鉴权。
- 禁止向 RN 暴露无限制的 URL 请求、任意原生方法执行或任意文件读写接口。
- 不兼容变更提升契约版本；新增能力必须声明宿主支持范围，旧宿主明确降级或拒绝，不猜测兼容。

## 6. 状态、设备通信与任务

- 每类生产状态只有一个权威所有者：账号、设备会话及任务在原生；RN 保留选项卡、输入、弹窗等页面状态。
- 原生首页与 RN 设备页消费同一设备服务。MQTT 连接数量按凭证、Client ID 和 Broker 约束确定，不按页面重复连接。
- MQTT 断线后恢复订阅和快照；命令提交成功不等于设备执行成功。区分发送、云端接受、设备确认、超时与结果未知。
- 未确认命令不自动重放；重试需依据接口幂等性，尤其避免重复触发维护、解绑或升级动作。
- BLE/Wi-Fi 配网由原生状态机管理，覆盖权限、扫描、连接、握手、下发、绑定、超时、取消与恢复。0822/0922 等协议仅按已确认契约实现，保留协议测试向量。
- 账号/租户切换、解绑和重连后拒绝旧会话回调；任务可观察且可查询最终状态，页面退出不擅自判定任务取消。
- RN 固件升级页展示原生任务。设备固件 OTA 与 RN 页面资源更新分别建模、版本管理和记录，禁止混用升级状态。

## 7. RN 设备组件与产品映射

- 开关、滑杆、模式、档位、定时、曲线及故障提示采用可组合的受控组件；组件接收状态及动作回调，不直接操作桥接或网络。
- 容器/用例层负责权限、异步动作和状态同步，展示组件只处理渲染与局部交互。
- 产品 ID、产品版本、物模型和能力通过适配层映射控件；禁止依靠产品名称、图片或页面位置猜测字段。
- 映射必须包含读写能力、类型、枚举、上下限、步长和单位；未知或不兼容能力明确提示并禁止错误控制。
- 每个控件定义加载、离线、禁用、发送中、失败和真实确认状态；高频状态更新按设备与字段拆分订阅，避免整页无差别重渲染。
- 曲线组件只有在业务范围和真实数据接口明确后启用，组件清单不授权新增历史数据业务。

## 8. RN 容器与生命周期

- 原生统一管理 runtime、设备入口、上下文、Bundle 版本及页面实例；明确创建、挂载、订阅、退出和销毁顺序。
- 同一 Bundle 的设备切换必须更新上下文并释放旧订阅；不同完整 Bundle 的切换策略先验证，禁止直接拼接独立 Metro Bundle。
- 账号变化、前后台切换、内存压力、JS 异常和原生异常均有对应处理及脱敏记录。
- 首版是否预热、复用或销毁 runtime 依据启动与内存实测确定，禁止仅以体验推测固定策略。
- Release 包内置可用资源，不依赖开发机或 Metro 服务。开发刷新只用于开发，不作为生产动态资源治理的替代。

## 9. 动态资源装载与版本治理

本节为待授权并技术验证后的实现规范，不表示已有更新服务。

- 原生负责解析目标版本、下载、校验、安装、激活、隔离及回退。页面不得自行下载执行代码。
- 资源解析以平台、产品/产品版本和兼容条件为依据；首版采用完整设备模块还是产品族 Bundle，先冻结发布粒度。
- Manifest 描述资源版本、平台、产品适配范围、宿主版本范围、RN/JS 引擎运行时标识、桥接/IoT SDK/物模型/API 兼容信息、URL、大小、Hash、签名信息、来源 Commit、发布时间和撤回状态。
- 下载使用可信 HTTPS 来源；在执行前验证 Manifest 签名、资源 Hash、大小、完整性及解包路径。Hash 不替代来源签名，公钥及轮换由宿主管理，私钥不进入客户端或仓库。
- 资源先下载到暂存区，全部校验通过后原子安装；只在安全时机激活，不替换正在操作的 runtime。
- 本地保留包内默认版本、已验证可用版本及候选状态；启动健康检查失败则隔离候选，回退到兼容可用版本，不反复加载坏包或已撤回版本。
- 启动或进入设备页检查适配关系；优先加载本地兼容资源，在线检查不应无条件阻塞每次进入。
- 离线可加载指页面资源可用，不等于依赖云端的控制业务离线可用。
- 灰度分组应稳定，支持暂停、撤回、回滚、最低宿主版本和强更策略。强更遇到断网或坏包时的行为须预先冻结，不允许死循环更新或加载不兼容包。
- 原生能力变化通过宿主发版解决；资源更新不能补齐原生依赖。资源更新应符合目标商店政策，不隐藏能力或绕过审核；发布前核对当时有效政策。
- 服务端版本解析、存储、签名发布和治理须明确责任及契约；客户端代码不冒充完整发布平台。

## 10. 页面样式与资源

- 将蓝湖确认的颜色、字号、间距、圆角及资源整理为有语义的设计令牌；原生与 RN 保持对应关系。
- 图片及字体在发布包内验证，禁止依赖开发机绝对路径；无授权资源不进入正式包。
- 页面布局处理安全区、状态栏、键盘、滚动与导航栏，避免宿主和 RN 重复添加边距。
- 设备控制触摸区域、读屏名称、字体缩放与明暗主题按实际需求验证，不以固定截图牺牲基本可操作性。
- 每页固定画板版本、设备尺寸、字号、语言和数据状态进行双端截图比对；同时检查小屏、大屏、加载、空态、错误、离线及弹窗状态。
- 迁移页面的功能和视觉均验收后再删除旧页面；记录允许的系统差异与待修复项，不宣称未经比对的像素级一致。

## 11. 配置、安全与日志

- 开发、预览、生产配置分开；禁止在页面中硬编码生产服务地址、账号、Token、签名私钥及设备秘密。
- 日志关联请求、会话、设备、宿主及资源版本；设备标识按需要脱敏。密码、验证码、Token、Cookie、Wi-Fi 密码和设备密钥不得输出。
- API 地址、权限及平台配置通过对应工程的正式配置管理。生产环境不得通过关闭 TLS 校验解决证书问题。
- 后台任务、设备连接和日志开销遵守平台生命周期约束；不以无必要的常驻服务绕过系统限制。

## 12. 工具链、依赖与升级

- 记录并锁定 RN、React、保留的 Expo 模块、JS 引擎、原生通信方式、JDK/Gradle/Android 工具链、Xcode/iOS 构建依赖及主要 SDK。
- 当前 package.json 为 Expo 57、RN 0.86.3 候选基线，不能以此认定新原生宿主已兼容。移除 Expo、替换模块或升级 RN 前完成双端验证。
- RN 源码、资源及锁文件在 app-rn；原生源码和平台依赖锁定信息随各端工程交付；不提交本机缓存、构建产物及凭据。
- 增加依赖说明用途、原生改动、许可、支持平台及对资源兼容性的影响，不为单个小功能无评估引入大型依赖。
- 原生依赖或桥接版本变化应重新验证 Bundle 兼容性；不将依赖大升级与业务迁移无关地混入同一改动。

## 13. 检查、测试与交付门槛

- 旧 RN 变更执行 `pnpm --dir app-rn-old lint`、`pnpm --dir app-rn-old typecheck`，并按影响范围执行测试、配置和 Bundle 验证。新 app-rn 尚未初始化，建立工程后配置并执行自己的 lint、typecheck 和相关验证，不以旧工程结果代表新模块通过。
- 原生工程建立后锁定可复现的构建、静态检查和测试命令；Android 与 iOS 分别执行，不以单端结果代替双端通过。
- 桥接覆盖成功、错误、超时、取消、重复事件、过期会话和订阅释放；原生协议实现复用既有测试向量进行一致性验证。
- 真机验收覆盖登录、配网、控制、定时、分享、固件升级、解绑、切账号、前后台、弱网与重连，按实际范围裁定。
- 资源治理验收覆盖正常加载、断网、下载中断、坏签名/Hash、损坏包、不兼容、启动失败、撤回、回滚和强更异常。
- 每次验收关联源码 Commit、宿主构建号、Bundle 版本/Hash、产品版本及测试设备。构建、静态检查或 Bundle 导出通过不能代替真实业务和视觉验收。
- 交付包括双端正式原生工程、RN 源码、桥接与配网代码、组件与资源、非秘密配置模板、依赖锁文件、构建和已授权发布/回滚脚本、实际验收记录及限制。
